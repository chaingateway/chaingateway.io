Webhooks

Webhooks

Sección titulada «Webhooks»

Descubra cómo la función de webhooks de Chaingateway puede ofrecer notificaciones de pago instantáneas a su servidor.

Introducción

Sección titulada «Introducción»

Los webhooks de Chaingateway ofrecen notificaciones de pago instantáneas en tiempo real al endpoint de sus sistemas. Para ello, debe crear un webhook justo antes de que se realice el pago. Este webhook cuenta con varias opciones de filtro y le proporciona información de la transacción en cuanto se liquida una transacción que coincide con sus criterios de filtro.

Cómo funciona un webhook

Sección titulada «Cómo funciona un webhook»

Webhooks: Los webhooks son una forma de que las aplicaciones envíen notificaciones en tiempo real a otras aplicaciones o servicios. En el contexto de la blockchain, los webhooks se pueden usar para recibir notificaciones sobre varios eventos, como nuevos bloques minados, transacciones confirmadas o eventos de smart contracts activados.

Al configurar un webhook, proporciona un endpoint URL en su aplicación que recibirá las notificaciones. Cada vez que ocurra el evento especificado, la red blockchain enviará una solicitud HTTP POST a su endpoint de webhook con los datos relevantes. Su aplicación puede entonces procesar estos datos y realizar las acciones adecuadas, como actualizar una base de datos, enviar notificaciones o activar otros procesos.

Instant Payment Notifications (IPN): Las IPN son un tipo específico de webhook utilizado en el contexto de sistemas de pago, incluidos los sistemas de pago basados en blockchain. Las IPN se usan normalmente para recibir notificaciones sobre eventos relacionados con pagos, como pagos exitosos, pagos fallidos o reembolsos.

Cuando se realiza un pago en una red blockchain, se puede activar una IPN para notificar a su aplicación sobre el estado del pago. Esto permite a su aplicación actualizar sus registros internos, ofrecer retroalimentación instantánea a los usuarios, o activar acciones adicionales según el estado del pago.

Tanto los webhooks como las IPN son esenciales para crear aplicaciones en tiempo real y basadas en eventos que interactúan con redes blockchain. Permiten que su aplicación se mantenga actualizada con los últimos eventos y tome medidas inmediatas basadas en ellos.

Flujo de trabajo

Sección titulada «Flujo de trabajo»

Para crear un webhook, debe seguir estos pasos:

  • Crear un endpoint receptor al que podamos enviarle los webhooks
  • Crear un webhook en Chaingateway usando el endpoint receptor
  • Esperar los eventos de la blockchain
  • Consumir la solicitud y devolver el código de respuesta correcto

Ejemplo de receptor

Sección titulada «Ejemplo de receptor»

Antes de crear un webhook, primero debe configurar un receptor. Un receptor de webhook es un componente o endpoint que escucha las solicitudes de webhook entrantes. Actúa como receptor o listener para eventos activados por sistemas o servicios externos. Cuando ocurre un evento de webhook, el sistema emisor realiza una solicitud HTTP a la URL del receptor de webhook, proporcionando los datos relacionados con el evento.

La función del receptor de webhook es gestionar y procesar las solicitudes de webhook entrantes. Normalmente realiza acciones basadas en los datos recibidos, como actualizar una base de datos, activar una notificación o ejecutar lógica de negocio específica.

Para configurar un receptor de webhook, debe definir un endpoint en su aplicación que pueda recibir solicitudes HTTP entrantes. Este endpoint debe ser públicamente accesible para que el sistema emisor pueda enviarle eventos de webhook. Una vez configurado el receptor, puede configurar el sistema emisor para que envíe los eventos de webhook a la URL del receptor.

::: tip Importante: Es fundamental que los receptores de webhook sean accesibles desde el exterior. Esto significa que las URL de endpoint definidas en los receptores de webhook deben ser públicamente accesibles para que los sistemas emisores puedan enviarles eventos de webhook. Asegúrese de configurar sus ajustes de red, cortafuegos y medidas de seguridad en consecuencia para permitir que las solicitudes HTTP entrantes lleguen a los receptores de webhook. :::

Ejemplo de creación

Sección titulada «Ejemplo de creación»

Una vez creado su receptor de webhook público, ya podemos crear el webhook.

Para crear un webhook, dispone de varias opciones para filtrar sus eventos relevantes.

  • from (string): La dirección del remitente.
  • to (string): La dirección del destinatario.
  • contractaddress (string): La dirección de un contrato que desea rastrear.
  • token_id (string): Un ID de token NFT.
  • type (string enum): El tipo de activo a rastrear. Los valores posibles para Ethereum son ETH, ERC20 o ERC721. Consulte la documentación para otras chains.

También debe añadir el parámetro url, que debe ser un nombre de dominio totalmente cualificado o una dirección IP con la ruta hacia el endpoint receptor de webhook que creó anteriormente.

Esto implica un conjunto requerido de «url» y uno de «from» o «to». El resto es opcional.
