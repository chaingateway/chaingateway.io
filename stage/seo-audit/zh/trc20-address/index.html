TRC20 地址是什么样的？

TRC20 地址是 TRON 账户地址的 Base58Check 形式，例如 TNPeeaaFB7K9cmo4uQpcU32zGK8G1NYqeL。它有 34 个字符，以 T 开头。TRON 的账户文档把底层的值定义为 21 字节：开头是 0x41 前缀字节，后面 20 字节与由同一公钥派生的 Ethereum 地址一致。

因此同一个地址还有一种 42 个字符、以 41 开头的十六进制写法。节点 API 常返回这种形式，而钱包和区块浏览器显示的是 Base58Check 形式。TronWeb 用 tronWeb.address.toHex() 和 fromHex() 在两者之间转换。

「TRC20」指的是代币标准，不是地址。TRC-20 是 TRON 的同质化代币标准，在接口层面与 Ethereum 的 ERC-20 兼容。一个 TRON 地址持有 TRX 和所有 TRC-20 代币。

TRC20 地址与 TRC20 合约地址是同一个东西吗？

不是。钱包地址是由私钥控制的账户。合约地址属于已部署的代码，没有人持有它的密钥。TRON 文档把两者都列为账户类型，两者也都写成以 T 开头的字符串，所以字符串本身无法区分。

合约地址标识的是哪一种代币在转移，它绝不是转账的收款地址。USDT 的 TRC-20 合约是 TR7NHqjeKQxGTCi8q8ZY4pL8otSzgjLj6t，发送到合约地址的代币在几乎所有情况下都无法找回。博客指南更详细地解释了两者的区别。

为什么新生成的 TRC20 地址在 Tronscan 上查不到？

因为 TRON 只有在账户激活之后才会识别它。按 TRON 账户文档，新生成的密钥对只存在于本地，在激活之前，无法通过 API 或区块浏览器查到这个地址。

激活的方式是：已有账户向新地址发送任意数量的 TRX 或 TRC-10 代币，并由发送方支付账户创建费。文档撰写时给出的主网创建费是 1 TRX，围绕它规划付款流程之前，请先核对当前数值。生成的地址可以用于存款和 webhook，但不要指望区块浏览器在首次激活之前显示它。

TRC20 地址接口：创建、读取、监控、发送

四类任务，以及对应的路由。创建地址和注册 webhook 完全不需要私钥，只有发送才需要。

如何通过 REST 生成 TRC20 地址？

POST /api/v2/tron/addresses 创建一个地址。请求体只有一个可选字段 password，它决定托管模式。传入密码，私钥就用它加密保存，之后的转账用密码而不是私钥来认证。不传密码，响应会直接返回私钥，由你存入自己的保险库。API 参考明确说明密码不会被保存：密码丢了，钱包就无法恢复。换个角度说，别人也同样无法解锁它。

curl -X POST https://app.chaingateway.io/api/v2/tron/addresses \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"password": "a-strong-password-per-wallet"}'

如果你的平台本来就自己生成密钥，第二个路由更合适：POST /api/v2/tron/addresses/import 会登记你在别处派生的地址，连同其私钥和加密密码，此后 API 就能为它签名。只想监控的地址则两个调用都不需要，因为 webhook 订阅是通过地址字符串来引用地址的。

同一组里还有两个管理路由。POST /api/v2/tron/addresses/{address} 修改已存私钥的加密密码。DELETE /api/v2/tron/addresses/{address} 把地址从你的账户中移除，参考文档说明这也会减少你已用的地址数量。如果你接近套餐上限，值得把它接入回收过期存款地址的任务里。

如何监控 TRC20 地址的 USDT 到账？

靠轮询 Tronscan 来检查存款，是最容易悄悄出问题的做法。POST /api/v2/tron/webhooks 才是可以扩展的做法。参考文档只把 url 标为必填；to 把订阅限定为转入你地址的存款，from 限定为从该地址转出的转账，contractaddress 限定为单一代币。type 选择资产类别，可取 TRX、TRC10、TRC20 或 TRC721。reference 最多可放 255 个字符的自定义文本，订单号或客户 ID 就该放在这里，这样通知到达时已经带着你的查询键。

curl -X POST https://app.chaingateway.io/api/v2/tron/webhooks \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://your-backend.example/hooks/tron",
    "to": "TYourDepositAddress",
    "type": "TRC20",
    "contractaddress": "TR7NHqjeKQxGTCi8q8ZY4pL8otSzgjLj6t",
    "reference": "customer-4711"
  }'

在账户中设置个人密钥后，每次送达都会带一个 X-Signature 头，它是对载荷中 txid 做 HMAC-SHA256 后再 base64 编码的值。解析其他内容之前先验证它。失败的送达不会自动重发：GET /api/v2/tron/webhooks/notifications/failed 列出没有送达的通知，POST /api/v2/tron/webhooks/notifications/{id}/retry 则会再发送一次。条目在重试开始时离开失败列表，只有这次重试也失败，才会再回来。重试会把同一事件再送达一次，所以请把每笔已入账存款的交易哈希存在唯一约束之下，让数据库拒绝重复。签名代码和载荷格式见 webhook 指南。

如何从该地址发送 USDT-TRC20？

POST /api/v2/tron/transactions/trc20 需要四个字段：from、to、contractaddress 和 amount。金额是以代币为单位的普通数字，所以 25 USDT 就是 25，而不是按合约的 6 位小数放大后的值。另外还要传 password（密钥由 API 加密保管时）或 privatekey（密钥由你自己保管时）二选一。

contractaddress 字段把钱包地址和代币合约地址的区别变成了具体的集成规则：合约地址标识的是哪一种代币在转移，它绝不是收款地址。USDT 的合约地址是 TR7NHqjeKQxGTCi8q8ZY4pL8otSzgjLj6t，它应当填在 contractaddress 中，绝不能填在 to 里。发送到合约地址的代币在几乎所有情况下都无法找回。博客指南解释了两者为什么看起来一样：两者都是以 T 开头的字符串，字符串本身无法区分。

发送消耗 Energy 和 Bandwidth，接收则免费，所以存款系统是在归集时付费，而不是在存款时付费。TRON 手续费计算器可以估算某笔具体转账的费用，GET /api/v2/tron/chainparameters 返回实时的资源价格，这样你的代码不必写死一个会被治理投票改变的常量。

发送前如何校验 TRC20 地址？

用户一提交目标地址就检查，而不是等广播之后。TRC-20 地址有 34 个字符，以 T 开头，并带有 Base58Check 校验和，错一个字符就会破坏它，所以无需访问网络，就能区分格式正确的字符串和手误。想手动验证单个地址时，地址校验工具会在浏览器中对 TRC-20、ERC-20 和 BEP-20 做这项检查。

TRON 地址和 EVM 地址不会被误认，因为两者的格式差别明显：以 T 开头的字符串通不过 Ethereum 的校验，以 0x 开头的字符串通不过 TRON 的校验。TRON 的 TVM 能运行大部分为 EVM 编写的 Solidity 代码，但它是独立的运行时，有自己的资源计量方式（用 Energy 和 Bandwidth 代替 gas）和自己的地址编码。把「TRON EVM」当成字面意思，就是跨链地址错误的起点。
