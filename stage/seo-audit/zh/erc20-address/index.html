ERC-20 标准是什么？

ERC-20 是 Ethereum 上同质化代币的标准接口。EIP-20 定义了六个函数：totalSupply、balanceOf、transfer、transferFrom、approve 和 allowance，以及 Transfer 和 Approval 两个事件。实现了这些函数的合约就是合规的代币。因此钱包和交易所支持新代币时，不必为每个代币单独开发。

ethereum.org 的 ERC-20 概述用示例讲解了同一套接口。完整机制见我们的 ERC20 代币标准文章。本页只讲地址这一侧：ERC-20 地址是什么，以及如何在代码中使用。

ERC-20 地址是什么样的？

ERC-20 地址就是普通的 Ethereum 地址，例如 0x5aAeb6053F3E94C9b9A09f33669435E7Ef1BeAed。它由 0x 加 40 个十六进制字符组成，共 42 个字符。ethereum.org 账户文档把它描述为账户公钥 Keccak-256 哈希的最后 20 字节。

这个名称只在特定语境中出现。当讨论的是地址所持有的代币时，它才被称为「ERC-20 地址」。字符串本身没有任何标记表明它支持代币，同一个地址可以用于 ETH、所有 ERC-20 代币和 NFT。

balanceOf 如何读取 ERC-20 余额？

balanceOf(address) 是只读函数，返回某个地址的代币余额。余额并不存放在地址上，而是保存在代币的智能合约里，是一个以地址为键的映射，balanceOf 负责查询它。

直接调用它，意味着要对代币合约编码一个 JSON-RPC eth_call，再解码返回的十六进制数据。结果是以代币最小单位表示的整数，所以还必须读取 decimals()。许多稳定币用 6 位小数，其他的用 18 位，搞错小数位是造成相差一百万倍的常见原因。

Chaingateway API 替你完成编码和小数位处理。余额接口返回普通数字，原本的原始 RPC 问题就变成了一次普通的 REST 响应。

同一个 ERC-20 地址在 Polygon 和 Arbitrum 上也有效吗？

有效。Polygon 和 Arbitrum 与 EVM 兼容，所以它们的地址使用完全相同的 0x 格式。由同一私钥派生的地址，在 Ethereum、Polygon 和 Arbitrum 上是同一串字符。

但该地址上的代币并不共享。部署在 Ethereum 上的代币合约，在 Polygon 上并不存在，除非有人在那里部署它或桥接该资产。因此余额是各链独立的，即使地址相同。Polygon 上的代币遵循同一套 ERC-20 接口，所以一套代码路径就能服务这三条链。

ERC-721 与 ERC-721A：另一套标准，相同的地址格式

ERC-721 是 Ethereum 的非同质化代币标准。每个代币 ID 都是唯一的，这与 ERC-20 可互换的余额不同。EIP-721 规定了它的接口。

ERC-721A 是同一接口的 gas 优化实现，常用于批量铸造的系列。它改变的是合约内部存储数据的方式，而不是持有者地址的样子。两套标准都用同样的 0x 地址表示所有权。ERC721 代币标准文章深入讲解 NFT 一侧。

通过 REST 创建并读取 ERC-20 地址

六个路由覆盖了支付集成中地址的整个生命周期。

接口作用
POST /api/v2/ethereum/addresses生成新的 Ethereum 地址
POST /api/v2/ethereum/addresses/import导入私钥，让 API 能够代表该地址签名
GET /api/v2/ethereum/balances/{address}/erc20/{contract_address}单个 ERC-20 代币的余额，已解码
GET /api/v2/ethereum/balances/{address}/erc20钱包中所有代币的余额
POST /api/v2/ethereum/webhooks注册 webhook，监控该地址收到的 ERC-20 存款
POST /api/v2/ethereum/transactions/erc20从该地址发送 ERC-20 代币

把路径中的 /ethereum/ 换成 /polygon/ 或 /arbitrum/，请求格式保持不变，因为三条链共用同一种地址格式和 ERC-20 接口。

发送前如何校验 ERC-20 地址？

先用 ^0x[a-fA-F0-9]{40}$ 匹配字符串，这样可以排除长度错误和多余字符。如果地址中混有大小写字母，还要校验 EIP-55 校验和，只要有一个字母写错，校验就会失败。

格式检查无法告诉你收款方期望哪个网络，因为同一个地址在每条 EVM 链上都有效。请明确收集网络信息。绝不要把代币合约地址当作收款地址。地址校验工具可以在浏览器中对单个地址执行格式和校验和检查。

常见问题：ERC-20 地址

Ethereum 为每个账户使用的、以 0x 开头的 42 个字符地址格式，无论该账户是否持有 ERC-20 代币。当讨论的是它所持有的代币时，才在语境中称为 ERC-20 地址。

一组函数，包括 transfer、approve、balanceOf 等，Ethereum 上任何同质化代币合约都会实现它们，这样钱包和交易所无需为每个代币单独开发就能支持新代币。

balanceOf(address) 是每个 ERC-20 合约都提供的只读函数。直接调用它，需要对代币合约发起 eth_call 并解码十六进制响应；Chaingateway API 则直接返回解码后的余额。

Polygon 是一条区块链，不是代币，但它与 EVM 兼容，所以其上的代币实现的是与 Ethereum 代币相同的 ERC-20 接口，Polygon 地址也使用完全相同的 0x 格式。

ERC-721 NFT 标准的 gas 优化实现，常用于批量铸造的系列。它改变的是合约内部存储，而不是地址格式，所有权仍然对应一个标准的 0x 地址。
