如何发送 ERC-20 代币：钱包、代码与 API 方法

从钱包、使用 ethers.js 或通过 REST API 发送 ERC-20 代币。文章涵盖 Gas、小数位数、合约地址风险和安全的转账模式，说明如何确认转账已到账、如何避免资金损失，并给出一个 REST 调用示例，供直接参考。

发送 ERC-20 代币，就是调用该代币智能合约上的 transfer 函数。你可以通过钱包发送，通过 ethers.js 等库在代码中发送，也可以通过 REST API 发送。发送方以 ETH 而非代币支付网络手续费。本指南介绍每种方法，以及会导致资金损失的常见错误。

TL;DR

  • ERC-20 转账是对代币合约的调用，而不是像 ETH 那样的普通价值转移。接收地址和金额都放在调用数据中。
  • 即使发送钱包持有大量代币，也需要 ETH 支付 Gas。如果 ETH 为零，交易将失败。
  • 切勿把代币直接 transfer 到没有处理代币逻辑的合约中。与合约交互时，应使用 approve 和 transferFrom。
  • 在代码中，要处理代币的小数位数，以及不返回标准布尔值的代币。应使用安全库封装调用。
  • 如果你要构建一个代表用户发送代币的应用，REST API 可以省去节点、Nonce 和 Gas 的相关工作。下文会介绍这一点。

发送 ERC-20 代币时会发生什么？

发送 ETH 是在两个账户之间转移原生价值。发送 ERC-20 代币则是修改一本存储在代币合约内部的余额账本。你的钱包创建一笔以代币合约为收件地址的交易，然后该合约更新发送方和接收方的余额。

ERC-20 标准定义了每个合规代币都必须提供的方法：totalSupply、balanceOf、transfer、transferFrom、approve 和 allowance。正是这一共用接口，使得同一个钱包或同一段代码能够处理成千上万种不同的代币。原始规范是 2015 年 11 月发布的 EIP-20。

这种设计带来以下几点影响：

  • 交易的 to 字段是代币合约，而不是你要付款的人。真正的接收方编码在调用数据中。
  • 调用数据以函数选择器 0xa9059cbb 开头，即签名 transfer(address,uint256) 的哈希的前四个字节。随后是接收地址和金额，编码方式见 Solidity ABI 规范。
  • ERC-20 是一种代币标准，并不等同于以太坊本身。ETH 是该网络的原生货币。USDT 等代币则是运行在其上的合约。若想了解 Gas 与 ETH 的整体情况，请参阅我们的以太坊概述。

其他 EVM 链也使用相同的格式。我们关于 ERC20 代币标准的文章更深入地介绍了它的工作原理，而 ERC20 地址指南则说明了地址格式和余额查询。

发送前应检查什么？

大多数转账失败源于跳过了准备工作，而不是技术故障。请先检查以下几点。

  1. 你持有该代币且金额足够。 通过 balanceOf 或在钱包中确认余额。
  2. 你持有用于支付 Gas 的 ETH。 手续费以网络的原生货币支付，不会从你发送的代币中扣除。在 Polygon 或 BNB Chain 上，同样的逻辑适用于该链的原生币。只有代币而没有 ETH 的钱包无法发送任何东西。
  3. 你拥有确切的接收地址。 请复制粘贴，而不要手动输入。MetaMask 帮助中心提醒注意地址投毒，即攻击者在你的交易记录中植入形似的地址。
  4. 你知道所用的网络。 同一个地址格式可用于多条 EVM 链。在错误网络上发送的代币，不会到达接收方预期的位置。
  5. 接收方能够接收该代币。 在错误的网络上发送到交易所充值地址，或发送到无法处理代币的合约，都可能造成永久损失。
  6. 先用小额测试。 对于新的接收方或新的集成，先发送少量代币，确认到账后再发送全额。

方法一：从钱包发送

对于一次性转账，钱包是最简单的途径。Etherscan 关于发送 ETH 或代币的指南描述了大多数钱包遵循的相同流程：

  1. 打开钱包并选择发送选项。
  2. 选择要发送的代币。如果钱包列表中没有该代币，可粘贴代币合约地址将其添加。
  3. 粘贴接收方地址。
  4. 输入金额。
  5. 查看网络手续费。钱包会为你估算。
  6. 确认，然后在区块浏览器上追踪交易哈希，直到交易被确认。

有两个细节容易出错。第一，添加自定义代币时粘贴的代币合约地址必须是真实的，因为伪造的代币会使用相同的名称和符号。请从项目方自己的网站进行核实。第二，显示的手续费以 ETH 计，因此钱包中的 ETH 余额必须在你计划发送的 ETH 之外，额外覆盖这笔手续费。

方法二：用代码发送（ethers.js）

需要自动化转账的开发者可以直接调用合约。ethereum.org 关于使用 ethers.js 发送代币的教程展示了基本模式。另一篇 ethers.js 演练解释了它与 ETH 的关键区别：该交易不发送任何价值，而是调用代币的 transfer 函数，并传入目标地址和金额。

步骤如下：

  1. 创建一个连接到以太坊节点（你自己的节点或托管端点）的 provider。
  2. 用私钥或你控制的钱包创建 signer。
  3. 使用代币地址和一个仅包含 transfer、balanceOf 和 decimals 的最小 ABI 实例化代币合约。
  4. 使用代币的小数位数，将人类可读的金额转换为最小单位。
  5. 调用 transfer(recipient, amount)，并等待收据。

ethers.js 教程指出，该库可以发送 EIP-1559 交易，无需手动设置 Gas，它会自行选择 Gas 上限和默认优先费。使用 signer 时，它还会管理 Nonce。

下面是 ethers.js v6 的一个最小版本（ethers 文档）：

正确处理小数位数

代币以整数存储金额。一个小数位数为 18 的代币，会将 1.0 个代币表示为 1000000000000000000 个最小单位。decimals 字段是标准的一部分，但不同代币设置的值各不相同，EIP-20 正文将其视为可选的元数据。应始终从合约中读取 decimals，而不是假定为 18。硬编码错误的值会使金额偏差几个数量级。

不要盲目相信返回值

标准规定 transfer 返回一个布尔值。但并非所有代币都如此。有些不返回任何值，有些则会以意料之外的方式失败。OpenZeppelin 的 IERC20 接口是该标准的参考，而 OpenZeppelin 的 SafeERC20 库就是为了封装调用，使特殊的代币不会破坏你的逻辑。如果你的智能合约需要移动代币，请使用它。如果你的后端发送代币，则应检查交易收据的状态和发出的 Transfer 事件，而不是假定转账成功。

Gas 上限

根据 MetaMask 的指导，普通的 ETH 转账使用 21,000 的 Gas 上限。代币转账是合约调用，因此需要更多 Gas。每次发送前，应使用库的估算调用来估算 Gas，而不是硬编码一个数字，因为成本取决于代币合约的代码以及相关余额的状态。

方法三：通过 REST API 发送

上面的代码路径对于脚本来说没有问题。但在产品中，它会变成一连串的琐事：运营或租用节点访问、管理密钥、跟踪 Nonce 以避免并发发送相互冲突、估算 Gas、重试卡住的交易、解码日志以确认付款是否到账，并且要针对每条链重复以上所有工作。

统一的 API 可以把这一层工作从你的团队身上移走。使用 Chaingateway，你可以通过普通的 REST 调用创建钱包、发送代币，并读取已解码的交易数据。你的技术栈中不需要 web3.js 或 ethers.js，也无需运行节点。我们的以太坊 API 页面展示了 ERC-20 发送如何通过 REST 完成。

OpenAPI 定义（/openapi.yaml）要求提供 from、contractaddress、to 和 amount，另加 password 或 privatekey。Gas 字段是可选的。

X-Network: testnet 会在 Sepolia 上运行该请求。amount 是十进制的代币数量，因此你无需自行转换为最小单位。

同样的方法也适用于 Polygon、BNB Smart Chain 和 Arbitrum，而 Tron 与 Solana 有各自的代币端点。如果你之后要添加 Tron 上的 USDT，可阅读我们关于 TRC10 与 TRC20 对比的说明。对于 BNB Chain 地址，参见 BEP20 地址指南。

ERC-20 转账会在哪些地方出错？

向合约发送代币

transfer 函数并非为向智能合约存入资金而设计。如果合约中没有处理到账代币的逻辑，代币就会一直留在其余额中，无法取出。ethereum.org 的 ERC-20 页面描述了这一风险，包括发送到代币自身合约的代币，并报告截至 2024 年 6 月 20 日，已有至少价值 8,370 万美元的 ERC-20 代币以这种方式丢失。如果你编写合约，应添加一个函数，以便取回误发的代币。如果你需要合约接收用户的代币，标准模式是：用户先为该合约调用 approve，然后合约再调用 transferFrom。

没有 ETH 用于 Gas

只要发送方没有原生货币，交易就会失败，无论钱包中有多少代币。产品团队往往后期才发现这一点：用户收到了代币，想要转出，却做不到。解决办法是给钱包充入少量 ETH，或通过签名授权进行设计规避。

网络或地址错误

区块链不会撤销交易。在确认之前，请核实网络和地址，并对任何新的目标使用小额测试转账。

把代币与网络混淆

例如，USDT 存在于多条链上。当有人说他持有 USDT 时，应询问是哪一条网络。同一地址在各条链上可能看起来完全相同，但资金只存在于一条链上。

能否在不持有 ETH 的情况下发送代币？

一种新兴的用户入门方式，是让用户签署一条消息，由其他人提交交易并支付 Gas。EIP-3009（带授权的转账）定义了一些函数，使持有人可以委托他人支付 Gas，并通过 EIP-712 签名来执行转账。只有实现了该标准的代币合约才支持这一功能，因此在围绕它设计流程之前应先确认。对于初创企业而言，这可以消除获取 ETH 才能完成首次转账的门槛。

为什么应把转账视为一个工作流程？

transfer 调用本身编写起来只需要半个下午。真正耗时的是它周围的一切：知道付款何时到账、处理失败或卡住的交易、估算手续费，以及保管好密钥。没有确认事件的付款流程会迫使你不断轮询。没有已解码数据的充值流程则会迫使你解析原始日志。

先在测试网上进行小额转账，验证小数位数和收据，订阅事件以获取确认信息，然后再扩大交易量。

能否用 Chaingateway 自动化转账？

可以。对于应用内的付款、提现或充值，可以使用区块链 API 配合Webhook，在付款到达时收到通知。Webhook 不会自动重试：请使用 GET /api/v2/ethereum/webhooks/notifications/failed 列出失败的通知，并通过重试端点重新发送。价格页上的套餐起价为每月 49 欧元（Plus），每个套餐都提供 7 天免费试用。

如何确认转账已成功？

提交交易并不等同于完成付款。发送之后，请执行以下步骤：

  1. 立即保存交易哈希。
  2. 检查收据状态。已被打包的交易仍可能执行失败。
  3. 查找代币合约发出的 Transfer 事件，并核对预期的发送方、接收方和金额。该事件是 ERC-20 接口的一部分。
  4. 在放行商品或为余额入账之前，等待你的风险政策要求的确认数。
  5. 定期与 balanceOf 进行对账，以发现监听器可能遗漏的内容。

轮询对于小型脚本是可行的。对于生产环境，订阅通知意味着你的系统对事件作出响应，而不是反复询问。

常见问题

发送 ERC-20 代币需要 ETH 吗？

需要。网络手续费以 ETH 支付，而不是以你发送的代币支付。如果发送钱包没有 ETH，交易就会失败。在其他 EVM 链上，你需要该链的原生货币。

USDT 是 ERC-20 代币吗？

在以太坊上，USDT 存在 ERC-20 版本，它是基于该标准构建的使用最广泛的代币之一。它也存在于其他网络上，因此务必确认你发送所用的网络，以及接收方期望的网络。

ERC-20 与以太坊是同一回事吗？

不是。以太坊是区块链，ETH 是它的原生货币。ERC-20 是以太坊上代币合约所遵循的标准接口，因此钱包和应用可以用相同的方式处理不同的代币。

如果把 ERC-20 代币发送到合约地址，会发生什么？

如果接收合约没有处理到账代币的逻辑，这些代币通常会被卡住，能否取回取决于该合约是否包含救援函数。发送前请先检查接收方。与合约交互时，应使用 approve，然后是 transferFrom。

我可以不运行节点就发送 ERC-20 代币吗？

可以。手动发送可以使用钱包，如果你在构建应用，则可以使用 REST API。使用 API 时，服务商负责节点访问、签名流程和 Gas 估算，你的代码只需发出普通的 HTTP 请求。
