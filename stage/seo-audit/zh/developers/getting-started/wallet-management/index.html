区块链钱包管理与密钥存储

Chaingateway 中的钱包是一个地址，其私钥要么在你选择的密码保护下加密存储，要么只返回给你一次并仅保存在你这一侧。Chaingateway 不存储你的密码，因此无法恢复丢失的密钥。创建地址时选择模式：发送 password 为保护模式，省略它则为非安全模式。

密码保护钱包和非安全钱包有什么区别？

Section titled “密码保护钱包和非安全钱包有什么区别？”

在保护模式下，Chaingateway 用你的密码和自己的加密链对私钥加密。在非安全模式下，密钥会在创建响应中返回，你需要在每次交易时发送它。下表对比了这两种模式。

密码保护非安全
创建请求请求体包含 password没有 password
响应中的私钥没有有，仅一次
密钥存放位置在 Chaingateway 加密存储仅在你这里
为交易签名发送 password发送 privatekey
丢失密码或密钥无法恢复无法恢复
适用于长期使用的地址和收款地址临时地址和一次性地址

::: danger 请妥善保管你的密码 我们从不存储密码，所以如果你丢失了密码，我们无法恢复你钱包的私钥。请把密码保存在密钥管理工具中，而不是代码仓库里。 :::

如何修改密码、导出密钥或导入现有密钥？

Section titled “如何修改密码、导出密钥或导入现有密钥？”

这些操作每条链各对应一个端点。下面的路径以 ethereum 为例，bsc、polygon 和 arbitrum 也有相同的路径。Tron 提供相同的地址操作，但不包括列出地址。

操作请求请求体
修改密码POST /api/v2/ethereum/addresses/{address}old_password、new_password（均为必填）
导出私钥POST /api/v2/ethereum/addresses/export/{address}password
导入现有密钥POST /api/v2/ethereum/addresses/importaddress、privatekey、password（均为必填）
列出你的地址GET /api/v2/ethereum/addresses无
删除地址DELETE /api/v2/ethereum/addresses/{address}无

修改密码使用 POST，而不是 PUT 或 PATCH。导入密钥会把现有地址变成密码保护地址。如果要对在别处创建的地址，或以非安全模式创建的地址使用保护模式，就用这种方式。导出响应以 data.private_key 返回密钥。删除地址会减少计入你套餐的地址数量。

什么时候应该使用非安全钱包？

Section titled “什么时候应该使用非安全钱包？”

非安全钱包只用于临时或一次性地址。如果省略密码，创建响应中会包含私钥，你必须自行保管。任何拿到该密钥的人都能控制该地址上的全部资金，而每次交易都要发送的密钥，会出现在你发出的每一个请求中。下面的请求创建一个不带密码的 Tron 地址。

响应包含 privateKey、publicKey、hexAddress 和 address。请先保存好密钥再做其他事情，因为之后的每笔交易都需要它。要从这样的地址发送，请在交易请求体中传入 privatekey，而不是 password。Tron 上的 TRX 和 TRC20 转账见创建交易和创建代币交易。

::: danger 仅用于非永久性钱包 由于私钥包含在响应中，你有责任存储并保护它。如果有人获得了你的私钥，他们就可以控制钱包中的所有资金。 :::

Bitcoin 和 Solana 上的钱包如何工作？

Section titled “Bitcoin 和 Solana 上的钱包如何工作？”

Bitcoin 和 Solana 使用 addresses 端点的方式与 EVM 链和 Tron 不同。

在 Bitcoin 上，钱包是地址的容器。带 password 的 POST /api/v2/bitcoin/wallets 会创建钱包，并以 data.bitcoinwallet 返回它的标识符。随后 POST /api/v2/bitcoin/wallets/{wallet}/addresses 向其中添加地址，POST /api/v2/bitcoin/wallets/{wallet}/addresses/{address}/export 则用钱包密码导出其中一个地址的密钥。Bitcoin 交易在 walletname 中指明钱包，并发送钱包的 password。达到套餐的地址数量上限时，API 会返回状态码 422，消息为 Your address limit exceeded. Please upgrade your plan。

在 Solana 上，POST /api/v2/solana/addresses 创建地址，每个交易请求都要携带发送方的 privatekey。OpenAPI 文件中没有 Solana 交易的密码模式，所以密钥的处理仍由你自己负责。

应该如何存储密钥和密码？

Section titled “应该如何存储密钥和密码？”

请把 API 令牌、钱包密码和私钥当作三份独立的机密。不要把它们放在同一个地方，也不要记录包含它们的请求体。OWASP Key Management Cheat Sheet 涵盖了从生成、存储到废弃的密钥生命周期。关于加密密钥本身的格式，Ethereum 提供了 Web3 secret storage 定义，其中描述了密码如何加密密钥。Bitcoin 钱包指南则介绍了钱包如何存储和派生密钥。
