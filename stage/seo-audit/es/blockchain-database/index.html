Comparación de modelos de datos

Base de datos blockchain: ¿es una blockchain realmente una base de datos?

Una base de datos blockchain es un registro replicado y de solo adición sobre el que una red de nodos se pone de acuerdo por consenso. Guarda datos estructurados y consultables como cualquier base de datos, pero nadie puede editar ni borrar un registro confirmado, y ningún operador la controla. Sirve para pagos y propiedad, no para datos generales.

Sí, una blockchain es una base de datos, con tres restricciones adicionales. Las escrituras son permanentes, cada full node guarda una copia íntegra y una escritura solo cuenta cuando la red se pone de acuerdo sobre ella. Esas restricciones son toda la diferencia entre ambos sistemas. También deciden cuándo una blockchain es la herramienta equivocada.

Esta página compara ambas propiedad por propiedad, explica cómo cambian los datos en un libro mayor de solo adición y muestra cómo leer datos de la cadena por una interfaz REST en lugar de JSON-RPC en bruto.

¿En qué se diferencia una blockchain de una base de datos tradicional?

Se diferencia en cinco propiedades: cómo funcionan las escrituras, quién controla los datos, cómo se confirma una escritura, cómo se almacenan los datos y cuánto cuesta escribir. Ninguna hace que un sistema sea estrictamente mejor. Se compensan entre sí.

EscriturasMutables: UPDATE y DELETE son operaciones normalesSolo por adición: un registro escrito nunca se edita ni se elimina
ControlCentralizado: un operador, una fuente de verdadDescentralizado: ninguna parte controla el libro mayor
Confirmación de escrituraInmediata, sujeta a la lógica del propio operadorSujeta al consenso de la red, que lleva tiempo y una comisión
Modelo de almacenamientoUna copia (más réplicas y copias de seguridad que gestiona el operador)Replicación completa: cada full node guarda todo el historial

Lee la tabla como una lista de comprobación, no como un marcador. Si tu aplicación necesita escrituras rápidas, baratas y corregibles bajo el control de una sola parte, eso es la descripción del puesto de una base de datos, no de una blockchain.

¿Es una blockchain una base de datos o algo distinto?

Estructuralmente es una base de datos: datos organizados y persistentes que se pueden consultar. El Blockchain Technology Overview del NIST describe las blockchains como libros mayores digitales resistentes a la manipulación y que la dejan en evidencia, implementados de forma distribuida y normalmente sin una autoridad central.

Lo que hace que la gente pregunte es que una blockchain descarta dos supuestos que casi toda base de datos asume. Uno es que un operador de confianza gestiona las escrituras. El otro es que un error se corrige con una sentencia UPDATE.

Una blockchain funciona como base de datos cuando la ausencia de un operador de confianza es precisamente el objetivo. Los pagos y los registros de propiedad son los casos típicos, donde la verificación independiente importa más que poder editar.

¿Cómo pueden cambiar los datos si una blockchain solo añade?

Cambian añadiendo un registro más nuevo que sustituye al anterior, mientras el anterior permanece. El NIST describe exactamente este patrón: las aplicaciones que usan una blockchain como capa de datos tratan las transacciones posteriores como actualizaciones de las anteriores. La capa de software muestra el estado vigente y la cadena conserva el historial completo de cambios.

Un saldo es el ejemplo cotidiano. Nadie edita un número en una tabla. Cada transferencia es una transacción nueva, y el saldo nuevo resulta de aplicarla al estado anterior. Un pago erróneo no se borra. Lo corrige una segunda transacción en sentido contrario, si el destinatario está de acuerdo.

¿Qué diferencia en la práctica a una blockchain de una base de datos normal?

Tres mecanismos hacen el trabajo. El primero es el consenso. Una escritura no es definitiva hasta que suficientes participantes independientes se ponen de acuerdo, lo que hace fiable el registro sin una autoridad central. También hace las escrituras más lentas y con coste que un INSERT de base de datos.

El segundo es la inmutabilidad por diseño. Una vez confirmado un bloque, alterarlo exigiría repetir el trabajo de consenso de todos los bloques posteriores, algo computacionalmente inviable a cualquier profundidad relevante. El whitepaper de Bitcoin describe esta cadena de bloques enlazados por hash, cada uno comprometido con el anterior.

El tercero es la replicación como característica y no como decisión de operaciones. Cada full node guarda todo el historial. Una base de datos tradicional solo obtiene esa redundancia si alguien la configura de forma explícita.

¿Por qué encaja una blockchain con los datos de pagos?

Para los datos de pagos, el equilibrio favorece a la blockchain. Quieres registros de solo adición y sujetos a consenso, porque nadie, tú incluido, debería poder editar en silencio una transacción liquidada. Lo que no quieres es una consulta JSON-RPC en bruto cada vez que necesitas un saldo o el estado de una transacción.

Esa parte la resuelve mejor una interfaz de base de datos. Una capa de API sobre la cadena te da ambas cosas: las garantías de la blockchain para el registro subyacente y una interfaz REST similar a una base de datos para leerlo. Preguntas frecuentes: blockchain y bases de datos

Estructuralmente sí: son datos organizados, persistentes y consultables. Lo que la distingue de una base de datos normal es que las escrituras son de solo adición, las autoriza el consenso de la red y no un único operador, y se replican por completo en cada nodo.

Una base de datos tradicional permite escrituras mutables bajo el control de un operador, con confirmación inmediata. Una blockchain solo permite escrituras de solo adición, confirmadas por consenso descentralizado, replicadas en cada full node y con una comisión en cada escritura.

Sí, para operaciones de lectura y adición: consultar saldos, historial de transacciones y estado confirmado funciona como consultar cualquier base de datos. Lo que no puedes hacer es UPDATE o DELETE sobre un registro confirmado, porque la inmutabilidad es el objetivo del diseño.

Tres cosas que una base de datos normal no tiene por defecto: escrituras sujetas a consenso en lugar de controladas por un operador, replicación completa de todo el historial en cada nodo, y registros permanentes e inalterables en lugar de filas editables.

Podrías, pero confiarías en que quien la opera no altere el libro mayor. Una blockchain elimina ese requisito de confianza a cambio de escrituras más lentas y con comisión. Ese compromiso importa en concreto porque los registros de pagos ganan al ser verificables de forma independiente en lugar de editables.
