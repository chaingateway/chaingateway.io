Wallet-Verwaltung und Schlüsselspeicherung

Ein Wallet in Chaingateway ist eine Adresse, deren Private Key entweder verschlüsselt hinter Ihrem Passwort liegt oder Ihnen einmalig zurückgegeben wird und nur bei Ihnen bleibt. Chaingateway speichert Ihr Passwort nicht und kann einen verlorenen Schlüssel nicht wiederherstellen. Den Modus wählen Sie beim Erstellen: password senden für den geschützten, weglassen für den ungesicherten.

Was unterscheidet passwortgeschützte von ungesicherten Wallets?

Im geschützten Modus verschlüsselt Chaingateway den Private Key mit Ihrem Passwort und einer eigenen Verschlüsselungskette. Im ungesicherten Modus wird der Schlüssel in der Antwort auf das Erstellen zurückgegeben, und Sie senden ihn mit jeder Transaktion. Die Tabelle vergleicht beide.

Wie erstelle ich ein passwortgeschütztes Wallet?

Senden Sie eine POST-Anfrage an /api/v2/{blockchain}/addresses mit einem password im JSON-Body. Ersetzen Sie {blockchain} durch ethereum, bsc, polygon, arbitrum oder tron. Das Beispiel erstellt eine Ethereum-Adresse.

Wie ändere ich das Passwort, exportiere den Schlüssel oder importiere einen vorhandenen Schlüssel?

Abschnitt betitelt „Wie ändere ich das Passwort, exportiere den Schlüssel oder importiere einen vorhandenen Schlüssel?“

Jede dieser Aktionen ist ein Endpunkt pro Chain. Die Pfade unten verwenden ethereum, dieselben Pfade gibt es für bsc, polygon und arbitrum. Tron bietet dieselben Adressoperationen, außer dem Auflisten von Adressen.

AktionAnfrageBody
Passwort ändernPOST /api/v2/ethereum/addresses/{address}old_password, new_password (beide erforderlich)
Private Key exportierenPOST /api/v2/ethereum/addresses/export/{address}password
Vorhandenen Schlüssel importierenPOST /api/v2/ethereum/addresses/importaddress, privatekey, password (alle erforderlich)
Ihre Adressen auflistenGET /api/v2/ethereum/addresseskeiner
Adresse löschenDELETE /api/v2/ethereum/addresses/{address}keiner

Die Passwortänderung ist ein POST, kein PUT oder PATCH. Der Import eines Schlüssels macht aus einer vorhandenen Adresse eine passwortgeschützte. So nutzen Sie den geschützten Modus für eine Adresse, die anderswo oder im ungesicherten Modus erstellt wurde. Die Export-Antwort liefert den Schlüssel als data.private_key. Das Löschen einer Adresse senkt die Zahl der Adressen, die auf Ihren Plan angerechnet werden.

Wann sollte ich ein ungesichertes Wallet verwenden?

Abschnitt betitelt „Wann sollte ich ein ungesichertes Wallet verwenden?“

Verwenden Sie ein ungesichertes Wallet nur für temporäre Adressen oder Einmal-Adressen. Wenn Sie das Passwort weglassen, enthält die Antwort auf das Erstellen den Private Key, und Sie müssen ihn selbst aufbewahren. Wer den Schlüssel erhält, kontrolliert alle Gelder auf der Adresse, und ein Schlüssel, den Sie mit jeder Transaktion senden, steht in jeder Ihrer Anfragen. Die folgende Anfrage erstellt eine Tron-Adresse ohne Passwort.

Die Antwort enthält privateKey, publicKey, hexAddress und address. Speichern Sie den Schlüssel, bevor Sie irgendetwas anderes tun, denn Sie brauchen ihn für jede spätere Transaktion. Um von einer solchen Adresse zu senden, übergeben Sie im Transaktions-Body privatekey statt password. TRX- und TRC20-Überweisungen auf Tron beschreiben Transaktionen erstellen und Token-Transaktionen erstellen.

::: danger Nur für nicht-dauerhafte Wallets verwenden Da der Private Key in der Antwort enthalten ist, liegt es in Ihrer Verantwortung, ihn zu speichern und zu schützen. Wenn jemand Zugriff auf Ihren Private Key erhält, kann diese Person alle Gelder im Wallet kontrollieren. :::

Wie funktionieren Wallets auf Bitcoin und Solana?

Abschnitt betitelt „Wie funktionieren Wallets auf Bitcoin und Solana?“

Bitcoin und Solana verwenden den Endpunkt addresses nicht auf dieselbe Weise wie die EVM-Chains und Tron.

Auf Bitcoin ist ein Wallet ein Container für Adressen. POST /api/v2/bitcoin/wallets mit einem password erstellt das Wallet und liefert seinen Bezeichner als data.bitcoinwallet. POST /api/v2/bitcoin/wallets/{wallet}/addresses fügt ihm danach Adressen hinzu, und POST /api/v2/bitcoin/wallets/{wallet}/addresses/{address}/export exportiert den Schlüssel einer Adresse mit dem Wallet-Passwort. Eine Bitcoin-Transaktion nennt das Wallet in walletname und sendet das Wallet-password. Ist das Adresslimit des Plans erreicht, antwortet die API mit Status 422 und der Meldung Your address limit exceeded. Please upgrade your plan.

Auf Solana erstellt POST /api/v2/solana/addresses eine Adresse, und jede Transaktionsanfrage enthält den privatekey des Absenders. Die OpenAPI-Datei kennt für Solana-Transaktionen keinen Passwortmodus, die Schlüsselverwaltung bleibt also bei Ihnen.

Wie sollte ich Schlüssel und Passwörter aufbewahren?

Abschnitt betitelt „Wie sollte ich Schlüssel und Passwörter aufbewahren?“

Behandeln Sie den API-Token, Wallet-Passwörter und Private Keys als drei getrennte Geheimnisse. Bewahren Sie sie nicht am selben Ort auf und protokollieren Sie keine Request-Bodys, die sie enthalten. Das OWASP Key Management Cheat Sheet behandelt den Lebenszyklus von Schlüsseln von der Erzeugung bis zu Speicherung und Stilllegung. Zum verschlüsselten Schlüsselformat selbst dokumentiert Ethereum die Web3-Secret-Storage-Definition, die beschreibt, wie ein Passwort einen Schlüssel verschlüsselt. Der Bitcoin-Wallet-Leitfaden beschreibt, wie Wallets Schlüssel speichern und ableiten.
