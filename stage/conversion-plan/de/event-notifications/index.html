Sofortige Zahlungsbenachrichtigungen implementieren

Zahlungen auf der Blockchain zu verfolgen kann komplex sein. Unsere Webhook-Lösung vereinfacht das, indem sie Echtzeit-Benachrichtigungen für Blockchain-Events liefert, sodass Sie kein Transaktions-Update verpassen.

Damit verfolgen Sie eingehende und ausgehende Transaktionen und filtern Events nach bestimmten Kriterien wie Transaktionstyp, Betrag oder beteiligten Adressen und Contracts. Dieser Grad an Anpassung stellt sicher, dass Sie nur die relevantesten Benachrichtigungen erhalten, damit Sie organisiert bleiben und schnell auf Ihre Blockchain-Aktivitäten reagieren können.

Chaingateway Webhooks ist ein Dienst, mit dem Sie Echtzeit-Benachrichtigungen für Blockchain-Events wie eingehende und ausgehende Transaktionen erhalten — durch POST-Requests an den von Ihnen angegebenen Endpoint, sobald relevante Events auftreten.

Eine Instant Payment Notification (IPN) ist eine Nachricht, die Chaingateway an den von Ihnen angegebenen Endpoint sendet, sobald ein relevantes Blockchain-Event auftritt, etwa eine eingehende oder ausgehende Transaktion. So erhalten Sie Echtzeit-Updates und können auf Basis der Event-Daten sofort reagieren.

Um einen Webhook einzurichten, benötigen Sie einen sicheren Endpoint auf Ihrem Server, der POST-Requests empfangen kann. Anschließend erstellen Sie über das Chaingateway-Dashboard oder die API einen Webhook und geben die URL Ihres Endpoints sowie die gewünschten Filter für die Events an, über die Sie benachrichtigt werden möchten.

Sie müssen url (öffentlicher Endpoint) sowie mindestens from oder to angeben. Zusätzliche optionale Filterparameter sind contractaddress, token_id und type (ETH/ERC20/ERC721 für Ethereum, entsprechend für andere Chains).

Jeder POST enthält id, webhook_id, from, to, blocknumber, datetime, tokenid, type, contractaddress, txid, amount und weitere Buchhaltungsfelder, damit Sie alles zum Abgleich von Zahlungen haben.

Jede Zustellung wird mit X-Signature signiert (HMAC SHA-256 über txid + Ihr Secret, Base64). Fehlgeschlagene Aufrufe werden 72 Stunden lang wiederholt und erscheinen im Zustellungsprotokoll, sodass Sie sie erneut senden oder alarmieren können; Test-Events helfen, Ihren Handler während der Entwicklung zu validieren.

Senden Sie über das Chaingateway-Dashboard Test-Events an Ihren Endpoint, um zu prüfen, ob Ihr Handler den Payload korrekt verarbeitet, bevor Sie live gehen.

Nutzen Sie den X-Signature-Header, um zu prüfen, dass eingehende Requests wirklich von Chaingateway stammen. Diese Signatur wird mit HMAC SHA-256 und Ihrem Secret Key erzeugt, sodass Ihr Endpoint nur autorisierte Events verarbeitet.
