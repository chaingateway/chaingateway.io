Ethereum: ETH, Gas-Gebühren und ERC-20-Token erklärt

What Ethereum is, how gas fees and ERC-20 tokens work, and how the Chaingateway API sends and receives both without running a node.

Ethereum ist eine öffentliche Blockchain, die Smart Contracts ausführt – On-Chain gespeicherter Code, der genau so läuft, wie er geschrieben ist – und darauf zwei Arten von Werten abwickelt: ETH, die native Währung, und Token, die innerhalb ETH-denominierter Contracts nach Standards wie ERC-20 gebaut sind. Diese Seite erklärt, was das in der Praxis bedeutet: wer Gas zahlt, wie sich ein Token-Transfer von einem ETH-Transfer unterscheidet, und wie Finalität unter Proof of Stake funktioniert. Für die technische Integration selbst sendet und empfängt die Chaingateway Ethereum API beides per REST, ohne synchronisierte Node und ohne Bibliothek wie web3.js hinter Ihrem Code.

Was Ethereum abwickelt: ETH und Token

Ethereum wickelt ETH selbst ab sowie Token, die innerhalb ETH-denominierter Smart Contracts leben. ERC-20 ist der Token-Standard hinter USDT, USDC, DAI und Tausenden weiteren Assets – eine gemeinsame Contract-Schnittstelle (balanceOf, transfer, approve), die jede Wallet oder Börse mit jedem konformen Token gleich interagieren lässt. ERC-721 und ERC-1155 erweitern dasselbe Contract-Modell auf nicht-fungible und Multi-Token-Assets. Unser ERC-20-Token-Standard-Guide behandelt das Format ausführlicher, und der ERC-20-Adress-Guide erklärt, wie sich eine Adresse von einem Token-Contract unterscheidet.

Gas: wer zahlt, und wie viel

Jede Ethereum-Transaktion kostet Gas, bezahlt in ETH von der sendenden Adresse – nie vom Empfänger. Ein einfacher ETH-Transfer kostet exakt 21.000 Gas; ein ERC-20-Transfer führt Contract-Code aus und kostet ein Vielfaches davon, variierend je Token. Seit dem London-Upgrade (EIP-1559) teilt sich der Preis pro Gas-Einheit in eine Basisgebühr, die das Netzwerk verbrennt, und einen Priority-Tip an den Block-Proposer, und beide steigen bei Netzwerklast. Eine Wallet mit Token, aber ohne ETH, kann diese nicht senden, weil der Token-Contract keine Möglichkeit hat, seine eigenen Ausführungskosten zu decken – die Wallet braucht ETH neben ihrem Token-Guthaben. Token oder ETH empfangen kostet den Empfänger nichts; Gas wird erst relevant, wenn Gelder wieder rausgehen, auch wenn eine Treasury-Wallet Deposits von Kundenadressen einsammelt.

In der Chaingateway API sind Gas-Limit, Gas-Preis und die EIP-1559-Caps (maxFeePerGas, maxPriorityFeePerGas) optionale Felder im Transaktions-Request. Lassen Sie sie weg, setzt die API sie, wenn sie Ihre Transaktion baut und broadcastet; übergeben Sie sie, wenn Sie die Gebühr fixieren wollen.

Proof of Stake: Blockzeiten und Finalität

Ethereum läuft seit dem Merge auf Proof of Stake. Blöcke kommen in festen Zwölf-Sekunden-Slots, 32 Slots bilden eine 6,4-Minuten-Epoche, und ein Block wird nach etwa zwei Epochen final – rund 13 Minuten –, sobald zwei Drittel des gestakten ETH ihn attestiert haben (Protokollparameter Stand Mitte 2026). Final bedeutet, das Netzwerk kann den Block nicht zurücknehmen, ohne einen großen Anteil des gesamten gestakten ETH zu zerstören. Ein Transfer ist typischerweise innerhalb von Sekunden bis einer Minute in einem Block enthalten; jeder weitere Slot erhöht die Sicherheit. Die meisten Anwendungen schreiben normal große Deposits nach Inklusion plus einer Handvoll Blöcke gut und reservieren die volle 13-Minuten-Wartezeit für große Beträge – der Deposit-Webhook liefert das On-Chain-Event, und wo die Gutschrift-Grenze liegt, ist eine Policy-Entscheidung in Ihrem eigenen Code.

Ethereum per REST senden und empfangen

Webhooks

Registrieren Sie eine Callback-URL und erhalten Sie eine HTTPS-Benachrichtigung, signiert mit einem X-Signature-Header, sobald ein Deposit abgewickelt ist. Die Zustellung hat kein eingebautes automatisches Retry – fehlgeschlagene Benachrichtigungen listet GET /api/v2/ethereum/webhooks/notifications/failed, und Sie lassen sich mit einem Aufruf erneut senden.

Einfache Transaktionen

Senden Sie ETH und ERC-20-Token mit Gas-Limit, Gas-Preis und Nonce als optionalen Request-Feldern. Liefern Sie Empfänger, Token und Betrag, und die API füllt den Rest, oder pinnen Sie die Gebührenfelder selbst, wenn Sie Kontrolle wollen.

Sichere Adressverwaltung

Das Adressformat wird bei jedem Request validiert, und bestehende Keys kommen über POST /api/v2/ethereum/addresses/import herein, passwortgeschützt und verschlüsselt gespeichert. Die Architektur ist non-custodial.

Dekodierte Abfragen

Transaktionen kommen als lesbares JSON über GET /api/v2/ethereum/transactions/{txid}/decoded zurück, sodass Ihre Anwendung strukturierte Felder liest, statt rohen Contract-Output zu parsen.

In drei Schritten loslegen

Step 1

Erstellen Sie ein Konto und kopieren Sie Ihren API-Key aus dem Dashboard. Der 7-Tage-Test startet ohne Kreditkarte und ohne KYC.

Step 2

Rufen Sie GET /api/account auf, um zu bestätigen, dass der Key funktioniert, erstellen Sie dann eine Adresse oder importieren Sie eine bestehende über POST /api/v2/ethereum/addresses/import.

Step 3

Fügen Sie den Header X-Network: testnet hinzu, füllen Sie die Adresse aus einem öffentlichen Sepolia-Faucet, und senden Sie einen Test-ERC-20-Transfer. Registrieren Sie einen Webhook, entfernen Sie dann den Header – derselbe Code läuft auf Mainnet.

Ethereum, Polygon und Arbitrum: ein Request-Format

Das ERC-20-Anfragemuster, das Ethereum nutzt, wiederholt sich auf den anderen EVM-Chains der API: /api/v2/polygon/transactions/erc20 und /api/v2/arbitrum/transactions/erc20 nehmen dieselben Felder wie Ethereums eigene Route, und BNB Smart Chain nutzt /api/v2/bsc/transactions/bep20. Für Ethereum geschriebener Code portiert zu Polygon oder Arbitrum durch Editieren des Pfads, was zählt, wenn Mainnet-Gas einen kleinen Transfer unwirtschaftlich macht. Die vollständige Chain-Liste steht in der Blockchain-API-Übersicht.
