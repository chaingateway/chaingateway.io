NFTs per API übertragen: Schritte, Parameter, Fallstricke

Wie eine NFT-Transfer-API arbeitet: Eigentumsprüfung, Parameter, Gas, Signatur, Bestätigung und typische Fehler, mit ERC-721-Beispielen für Ethereum und Tron.

Kapitel
C
Chaingateway Team
Blockchain-Experten

Geprüft von Maurice Sobiera

Eine NFT-Transfer-API lässt Ihr Backend einen Token mit einer einzigen HTTP-Anfrage zwischen Wallets verschieben. Sie prüft die Eigentümerschaft, baut den Aufruf für den Token-Standard, signiert und sendet die Transaktion und meldet das Ergebnis zurück. Jeder Transfer bleibt eine On-Chain-Transaktion, und der Absender zahlt die Gebühr.

Dieser Leitfaden geht jeden Schritt durch, die Parameter, die eine Anfrage braucht, und die Fehler, die Entwickler am meisten Zeit kosten.

TL;DR

  • Ein NFT-Transfer ändert den Eigentümer, der im Token-Contract vermerkt ist. Auf Ethereum-artigen Chains ist das ein Aufruf von transferFrom oder safeTransferFrom. Auf Solana ist es eine Instruktion des Token-Programms oder von Metaplex.
  • Eine Anfrage braucht vier Angaben: die Absender-Wallet, die Empfängeradresse, die Contract- (bzw. Mint-)Adresse und die Token-ID. ERC-1155 braucht zusätzlich eine Menge.
  • Prüfen Sie die Eigentümerschaft vor dem Senden, schätzen Sie die Gebühren vor dem Signieren und bestätigen Sie den Erfolg über die Chain (Receipt und Transfer-Event), nicht nur über die HTTP-Antwort.
  • Die häufigsten Fehler sind falsche Chain, Empfänger-Contracts, die keine NFTs annehmen können, fehlendes Gas in der nativen Währung und veraltete Eigentumsdaten.
  • Eine API entfernt die kettenspezifische Infrastruktur. Chaingateway sendet ERC-721-, BEP-721- und TRC-721-Transfers und bietet Webhooks zur Bestätigung, damit Sie nicht pollen müssen. Einen ERC-1155-Endpunkt und einen Solana-NFT-Endpunkt gibt es nicht.

Was macht eine NFT-Transfer-API?

Ein NFT ist ein Eintrag in einem Smart Contract (oder auf Solana in einem Token-Konto), der festlegt, welche Adresse welchen Token besitzt. Ihn zu übertragen heißt, diesen Eintrag zu ändern. Nur der Eigentümer oder jemand, den der Eigentümer dazu berechtigt hat, kann das tun.

Der ERC-721-Standard definiert das auf Contract-Ebene. Jeder Token ist über eine Token-ID identifiziert. Ein Transfer überträgt das Eigentum von einer Adresse auf eine andere, wenn der Eigentümer, eine freigegebene Adresse oder ein Operator ihn auslöst. Der Contract sendet dann ein Transfer-Event. Auf dieses Signal hören die meisten Indexer und Benachrichtigungssysteme.

Eine API setzt darauf auf. Eine gute API übernimmt fünf Aufgaben für Sie:

  1. Eigentumsprüfung: Bestätigen, dass die Absender-Wallet den Token aktuell besitzt.
  2. Aufbau des Aufrufs: Die richtige Funktion für Standard und Chain kodieren.
  3. Gebührenschätzung: Gas oder Netzwerkgebühren berechnen und prüfen, ob die Wallet sie zahlen kann.
  4. Signieren und Senden: Mit dem Schlüssel der Wallet signieren und die Transaktion einreichen.
  5. Statusmeldung: Einen Transaktions-Hash zurückgeben und melden, wann der Transfer endgültig ist.

Die Alternative ist ein eigener Node mit Web3-Bibliotheken für jede Chain und eigener Kodierung. Das funktioniert für eine Chain und eine Kollektion. Mit einem zweiten Netzwerk wird es teuer.

Welche NFT-Standards und Chains kann eine Transfer-API abdecken?

Nicht jedes NFT ist die gleiche Art von Objekt. Deshalb muss eine API mehr als einen Dialekt sprechen.

Standard / ModellChainsSo funktioniert der Transfer
ERC-721Ethereum, Polygon, Arbitrum und weitere EVM-ChainsEine Token-ID je Token; transferFrom oder safeTransferFrom
ERC-1155Ethereum und EVM-ChainsContract mit mehreren Token-Typen; der Transfer enthält eine Menge je Token-ID, auch Batch-Transfers
SPL-Token mit Supply eins + Metaplex-MetadatenSolanaTransfer über das Token-Programm; Metadaten separat gespeichert

ERC-1155 verdient einen genaueren Blick, wenn Sie Spielgegenstände oder Tickets verarbeiten. Ein Contract hält sowohl austauschbare als auch nicht austauschbare Typen. Seine Schnittstelle umfasst einzelne und sichere Batch-Transfers, und jeder Transfer trägt eine Menge für die Token-ID. Ein Token mit Supply eins verhält sich wie ein klassisches NFT. Eine Auflage mit Supply 500 ist dagegen ein anderer Fall: Sie müssen eine Menge senden, nicht nur eine ID.

Solana funktioniert anders. Dort wird in der Regel nicht für jede Kollektion ein eigener Contract deployt. NFTs sind Token des Token-Programms mit Supply eins. Die Metaplex Token Metadata enthalten die NFT-Details. Auf Solana übertragen Sie deshalb über die Mint-Adresse und nicht über Contract plus Token-ID. Der Empfänger braucht dafür ein Token-Konto für diesen Mint.

Prüfen Sie bei jedem Anbieter, welches dieser drei Modelle er auf welchen Chains unterstützt. Die OpenAPI-Datei von Chaingateway listet diese NFT-Endpunkte:

Wie überträgt man ein NFT Schritt für Schritt über eine API?

Der Ablauf ist bei jedem Anbieter derselbe. Unterschiedlich ist nur, wie viel Sie davon selbst schreiben.

1. Eigentum prüfen

Bevor Sie eine Transaktion bauen, bestätigen Sie, dass der Absender den Token tatsächlich besitzt. Bei ERC-721 bedeutet das, den Contract nach dem Eigentümer der Token-ID zu fragen. Bei ERC-1155 prüfen Sie das Guthaben dieser ID für die Adresse. Auf Solana prüfen Sie das Token-Konto, das den Mint hält.

Machen Sie das unmittelbar vor dem Senden und nicht anhand einer zwischengespeicherten Datenbankzeile. NFTs können in den Sekunden zwischen Ihrem letzten Abgleich und Ihrer Anfrage verkauft oder verschoben werden. Ein Transfer aus einer Wallet, die den Token nicht mehr besitzt, scheitert einfach. In manchen Fehlerfällen kostet er trotzdem Gebühren.

2. Berechtigung prüfen

Der Standard erlaubt dem Eigentümer, einer freigegebenen Adresse oder einem Operator, einen Transfer auszulösen. Wenn Ihr Dienst NFTs aus Wallets bewegt, die Nutzer besitzen und Sie nicht kontrollieren, brauchen Sie vorher eine Freigabe. Hält Ihr Dienst die Schlüssel für Wallets, die er selbst erstellt hat, wie bei verwahrenden Abläufen, ist die Absender-Wallet der Eigentümer. Dann ist keine Freigabe nötig.

3. Aufbauen und schätzen

Wählen Sie die Funktion und kodieren Sie die Argumente. Schätzen Sie danach die Gebühr. Auf EVM-Chains ergibt sich das aus einem Gas-Limit mal Gaspreis. Auf Solana fällt eine kleine Gebühr je Signatur an, gegebenenfalls zuzüglich der Miete für ein neues Token-Konto.

Die Chaingateway-Endpunkte nehmen optionale Felder gas, gasprice, maxFeePerGas und maxPriorityFeePerGas entgegen. Die EVM-Chains haben außerdem einen Endpunkt GET .../gasprice. Vermeiden Sie ein fest codiertes Gas-Limit, denn es scheitert, sobald der Empfänger ein Contract mit zusätzlicher Logik ist. Testen Sie im Testnetz, was eine Anfrage ohne diese Felder kostet.

Prüfen Sie außerdem, ob die Wallet genug von der nativen Währung hält. Eine Adresse mit zehn NFTs und null ETH kann keinen davon bewegen.

4. Signieren und senden

Die Transaktion muss mit dem privaten Schlüssel des Eigentümers signiert werden. Entweder signieren Sie lokal und senden die rohe Transaktion, oder die API signiert für eine Wallet, die sie verwaltet. Verwaltete Wallets sind für Backend-Abläufe einfacher, weil Ihre Server nie rohe Schlüssel anfassen.

5. Bestätigen

Ein Transaktions-Hash heißt, dass das Netzwerk Ihre Einreichung angenommen hat. Er heißt nicht, dass der Transfer erfolgreich war. Warten Sie auf einen Receipt mit Erfolgsstatus und auf das Transfer-Event mit dem erwarteten Absender, Empfänger und der erwarteten Token-ID. Bei hochpreisigen NFTs warten Sie auf mehrere Bestätigungen, bevor Sie Ihre eigene Datenbank aktualisieren oder im Gegenzug etwas freigeben.

Was braucht eine Transfer-Anfrage?

Unabhängig von den Feldnamen des Anbieters trägt die Anfrage dieselben Informationen.

ParameterWarum er nötig istHinweise
Chain / NetzwerkDieselbe Adresse existiert auf vielen EVM-ChainsMainnet oder Testnet ist das Erste, das Sie prüfen, wenn ein Token „verschwindet“
Absender-WalletLegt fest, wer signiert und zahltMuss den Token besitzen und Gas in nativer Währung halten
EmpfängeradresseZielFormat und Prüfsumme validieren; Freitext nie ohne Prüfung annehmen
Contract- oder Mint-AdresseIdentifiziert die KollektionContract auf EVM, Mint auf Solana
Token-IDIdentifiziert den einzelnen TokenAuf Solana nicht nötig, dort ist der Mint der Token
MengeAnzahl, die bewegt wirdFür ERC-1155 Pflicht; bei ERC-721 eins
GebühreneinstellungenGas-Limit und Preis oder Priority FeeLassen Sie die API schätzen, außer Sie haben einen Grund dagegen
Idempotenz oder ReferenzVerhindert doppeltes Senden bei WiederholungSpeichern Sie Ihre eigene Referenz zusammen mit dem Transaktions-Hash

Die letzte Zeile wiegt schwerer, als sie aussieht. Läuft Ihre Anfrage in einen Timeout, wissen Sie nicht, ob die Transaktion gesendet wurde. Ein blindes Wiederholen kann eine zweite Transaktion auslösen. Bei einem einzigartigen NFT scheitert sie einfach. Bei einer ERC-1155-Auflage kann sie aber zusätzliche Exemplare verschieben. Prüfen Sie daher zuerst den früheren Versuch.

Wie schätzt und zahlt man NFT-Transfergebühren?

In EVM-Netzwerken zahlt der Absender das Gas in der nativen Währung der Chain. Die Kosten schwanken mit der Netzwerkauslastung und der Komplexität des Aufrufs. Ein einfacher transferFrom ist günstig, verglichen mit einem Mint oder einem Marktplatzverkauf. Ein Empfänger-Contract mit einer aufwendigen Empfangsfunktion kann ihn aber erhöhen.

Praktische Regeln:

  • Schätzen Sie unmittelbar vor dem Senden und addieren Sie einen moderaten Puffer, statt einen festen Wert zu nutzen.
  • Halten Sie auf jeder Wallet, die NFTs sendet, ein Mindestguthaben in nativer Währung und lösen Sie einen Alarm aus, wenn es darunter fällt.
  • Wenn Sie im Auftrag von Nutzern übertragen, legen Sie vorab fest, wer zahlt: Sie (Sie laden die Wallet auf) oder der Nutzer (Abbuchung von einem Guthaben). Überraschungen an dieser Stelle werden zu Support-Tickets.
  • Auf Solana denken Sie daran, dass der Empfänger eventuell ein neues Token-Konto braucht. Das kostet einmalig.

Wie sichert man NFT-Transfers ab?

NFT-Transfers sind unumkehrbar. Auf der Chain gibt es keine Rückbuchung und keinen Support. Die Schutzmaßnahmen liegen deshalb in Ihrem Code.

Den Signaturweg schützen. Authentifizieren Sie jeden API-Aufruf. Chaingateway nutzt ein Bearer-Token im Header Authorization, wie in RFC 6750 definiert. Bewahren Sie das Token in einem Vault auf, rotieren Sie es und liefern Sie es nie in einer Browser- oder Mobile-App aus. Wallets, die mit einem Passwort erstellt wurden, speichern den Schlüssel verschlüsselt auf der Seite von Chaingateway. Wallets ohne Passwort geben den privaten Schlüssel bei der Erstellung zurück. Dann müssen Sie ihn selbst sicher aufbewahren.

Den Empfänger prüfen. Kontrollieren Sie Adressformat und Chain. Bieten Sie bei hochpreisigen Gegenständen einen Bestätigungsschritt an. Wo es Richtlinien verlangen, prüfen Sie Adressen vor dem Senden.

Auf Empfänger-Contracts achten. Die ERC-721-Spezifikation beschreibt, dass safeTransferFrom bei einem Contract als Ziel onERC721Received aufruft und zurückgesetzt wird, wenn der Rückgabewert falsch ist. So schützen Sie sich davor, einen Token in einem Contract festzusetzen, der ihn nicht bewegen kann. Bei einfachem transferFrom bleibt diese Prüfung dem Aufrufer überlassen. Die API-Referenz von Chaingateway sagt nicht, welche der beiden Funktionen sein ERC-721-Endpunkt aufruft. Testen Sie deshalb einen Transfer an eine Contract-Adresse im Testnetz, bevor Sie sich auf eines der beiden Verhalten verlassen.

Das Risiko begrenzen. Halten Sie eine Hot-Wallet nur mit den NFTs, die für kurzfristige Transfers nötig sind. Der Rest liegt in einer stärker eingeschränkten Wallet. Setzen Sie Limits pro Anfrage und pro Tag in Ihrer eigenen Schicht.

Alles protokollieren. Halten Sie fest, wer den Transfer angefordert hat, mit welchen Parametern, welcher Hash entstanden ist und wie das Ergebnis war. Streitet ein Kunde einen Transfer ab, belegt die Chain, was passiert ist. Ihre Protokolle belegen, wer es angefordert hat.

SymptomWahrscheinliche UrsacheLösung

Die meisten dieser Fehler fängt man mit zwei Gewohnheiten ab: Eigentum und Guthaben zuerst prüfen und den Receipt auf der Chain als einzigen Beleg für den Erfolg behandeln.

Wie bestätigt man Transfers mit Webhooks statt mit Polling?

Ein Transaktions-Hash alle paar Sekunden abzufragen, funktioniert im Prototyp und verschwendet im Betrieb Anfragen. Mit Webhooks ruft der Anbieter Ihren Endpunkt auf, sobald ein passender Transfer gesehen wird. Bei Chaingateway registrieren Sie einen Webhook mit type auf ERC721 (oder TRC721, BEP721), einer contractaddress und einem Filter für die Adresse from oder to. Die Benachrichtigung enthält from, to, contractaddress, tokenid, txid und blocknumber.

Prüfen Sie den Header X-Signature, antworten Sie zügig und verarbeiten Sie Events idempotent. Fehlgeschlagene Benachrichtigungen werden nicht automatisch wiederholt. Prüfen Sie deshalb auch die Liste der fehlgeschlagenen Benachrichtigungen.

Die Signatur deckt nur die txid ab. Gleichen Sie Token-ID und Empfänger deshalb mit Ihren eigenen Datensätzen ab. Wenn Sie verstehen wollen, wie solche Events auf Log-Ebene aussehen, behandelt unser Beitrag zum ERC-20-Transfer-Event Struktur und Topics. Das ERC-721-Event folgt demselben Muster, wobei die Token-ID indiziert ist.

Wie sendet man ein NFT mit Chaingateway?

Senden Sie eine Anfrage pro Token. Die Ethereum-Anfrage braucht die Absenderadresse, den Empfänger, die Contract-Adresse der Kollektion und die Token-ID. Für eine Wallet, die mit einem Passwort erstellt wurde, ergänzen Sie password. Für eine Wallet, deren Schlüssel Sie verwalten, ergänzen Sie privatekey:

Der Header X-Network: testnet wählt Sepolia. Für Mainnet entfernen Sie ihn. Ein Erfolg liefert den Status 201. Ein falsches Wallet-Passwort liefert 401 mit „Wrong password provided“. Ein leeres Gas-Guthaben liefert 422 mit der Meldung des Nodes, etwa insufficient funds for gas * price + value.

Was sollten Sie vor dem Start prüfen?

Bevor echte Nutzer NFT-Transfers auslösen können, gehen Sie diese Liste zuerst im Testnetz durch:

  1. Übertragen Sie einen Token, den Sie besitzen, an eine normale Wallet, und prüfen Sie Receipt und Transfer-Event.
  2. Übertragen Sie an einen Contract, der keine NFTs annehmen kann, und prüfen Sie, dass Ihr Code den Fehler anzeigt.
  3. Versuchen Sie einen Transfer aus einer Wallet ohne native Währung und prüfen Sie, dass die Fehlermeldung klar ist.
  4. Senden Sie dieselbe Anfrage zweimal und prüfen Sie, dass Ihre Idempotenzprüfung die zweite stoppt.
  5. Schalten Sie Ihren Webhook-Endpunkt für eine Minute ab, stellen Sie ihn wieder her und prüfen Sie, dass keine Events verloren gehen oder doppelt verarbeitet werden.
  6. Prüfen Sie, wer den Endpunkt mit welchen Limits aufrufen darf und wo das Secret gespeichert ist.
