Wie man ERC-20-Token sendet: Wallet, Code und API-Methoden

ERC-20-Token aus einer Wallet, mit ethers.js oder per REST-API senden. Behandelt Gas, Dezimalstellen, Risiken bei Vertragsadressen und sichere Transfer-Muster.

Kapitel
C
Chaingateway Team
Blockchain-Experten

Geprüft von Maurice Sobiera

Einen ERC-20-Token zu senden bedeutet, die Funktion transfer im Smart Contract des Tokens aufzurufen. Sie können das aus einer Wallet tun, aus Code mit einer Bibliothek wie ethers.js oder über eine REST-API. Der Absender zahlt die Netzwerkgebühr in ETH, nicht im Token. Dieser Leitfaden behandelt jede Methode und die Fehler, die Geld kosten.

TL;DR

  • Ein ERC-20-Transfer ist ein Aufruf des Token-Vertrags, kein einfacher Wertetransfer wie bei ETH. Empfängeradresse und Betrag stehen in den Call Data.
  • Die sendende Wallet braucht ETH für Gas, auch wenn sie viele Token hält. Ohne ETH scheitert die Transaktion.
  • Senden Sie Token nie mit transfer an einen Vertrag, der keinen Code zur Verarbeitung hat. Für Vertragsinteraktionen nutzen Sie approve und transferFrom.
  • Im Code behandeln Sie Dezimalstellen und Token, die keinen Standard-Booleschen-Wert zurückgeben. Umhüllen Sie Aufrufe mit einer sicheren Bibliothek.
  • Wenn Sie eine App bauen, die Token für Nutzer sendet, nimmt eine REST-API die Arbeit mit Node, Nonce und Gas ab. Dazu unten mehr.

Was passiert, wenn Sie einen ERC-20-Token senden?

Eine ETH-Überweisung bewegt nativen Wert zwischen zwei Konten. Ein ERC-20-Transfer ändert dagegen ein Saldenregister, das im Vertrag des Tokens gespeichert ist. Ihre Wallet erstellt eine Transaktion an den Token-Vertrag. Dieser Vertrag aktualisiert die Salden von Absender und Empfänger.

Der ERC-20-Standard legt die Methoden fest, die jeder konforme Token bereitstellt: totalSupply, balanceOf, transfer, transferFrom, approve und allowance. Diese gemeinsame Schnittstelle erlaubt es, dass eine Wallet oder ein Stück Code Tausende verschiedener Token verarbeitet. Die ursprüngliche Spezifikation ist EIP-20 aus dem November 2015.

Aus diesem Design folgen einige Konsequenzen:

  • Das Feld to der Transaktion ist der Token-Vertrag, nicht die Person, an die Sie zahlen. Der tatsächliche Empfänger steht in den Call Data.
  • Die Call Data beginnen mit dem Funktionsselektor 0xa9059cbb, den ersten vier Bytes des Hashs der Signatur transfer(address,uint256). Es folgen Empfängeradresse und Betrag, kodiert wie in der Solidity-ABI-Spezifikation beschrieben.
  • ERC-20 ist ein Token-Standard und nicht dasselbe wie Ethereum. ETH ist die native Währung des Netzwerks. Token wie USDT sind Verträge, die darauf laufen. Für das größere Bild zu Gas und ETH lesen Sie unsere Ethereum-Übersicht.

Dasselbe Format existiert auch auf anderen EVM-Chains. Unser Beitrag zum ERC20-Token-Standard geht genauer darauf ein, wie er funktioniert. Der ERC20-Adressleitfaden erklärt Adressformat und Saldenabfragen.

Was sollten Sie vor dem Senden prüfen?

Die meisten verlorenen Transfers entstehen durch übersprungene Vorbereitung, nicht durch technisches Versagen. Prüfen Sie diese Punkte zuerst.

  1. Sie halten den Token in der richtigen Menge. Prüfen Sie den Saldo mit balanceOf oder in Ihrer Wallet.
  2. Sie halten ETH für Gas. Die Gebühr wird in der nativen Währung des Netzwerks gezahlt. Sie wird nicht von den gesendeten Token abgezogen. Auf Polygon oder BNB Chain gilt dieselbe Logik mit der nativen Münze dieser Chain. Eine Wallet mit Token, aber ohne ETH, kann nichts senden.
  3. Sie haben die exakte Empfängeradresse. Kopieren und einfügen Sie sie, statt sie abzutippen. Das Hilfezentrum von MetaMask warnt vor Address Poisoning. Dabei legt ein Angreifer in Ihrem Verlauf eine ähnlich aussehende Adresse an.
  4. Sie kennen das Netzwerk. Dasselbe Adressformat funktioniert auf mehreren EVM-Chains. Ein Token, der im falschen Netzwerk gesendet wird, kommt nicht dort an, wo der Empfänger ihn erwartet.
  5. Der Empfänger kann ihn annehmen. Eine Überweisung an eine Einzahlungsadresse einer Börse im falschen Netzwerk oder an einen Vertrag, der Token nicht verarbeiten kann, kann zu dauerhaftem Verlust führen.
  6. Sie testen zuerst mit einem kleinen Betrag. Senden Sie bei einem neuen Empfänger oder einer neuen Integration einen kleinen Betrag. Prüfen Sie, dass er angekommen ist, bevor Sie die volle Summe senden.

Methode 1: Aus einer Wallet senden

Für einmalige Transfers ist eine Wallet der einfachste Weg. Der Etherscan-Leitfaden zum Senden von ETH oder Token beschreibt den Ablauf, dem die meisten Wallets folgen:

  1. Öffnen Sie die Wallet und wählen Sie die Sendefunktion.
  2. Wählen Sie den Token, den Sie senden wollen. Wenn die Wallet ihn nicht auflistet, fügen Sie ihn hinzu, indem Sie die Vertragsadresse des Tokens einfügen.
  3. Fügen Sie die Empfängeradresse ein.
  4. Geben Sie den Betrag ein.
  5. Prüfen Sie die Netzwerkgebühr. Die Wallet schätzt sie für Sie.
  6. Bestätigen Sie und verfolgen Sie den Transaktions-Hash in einem Block-Explorer, bis die Transaktion bestätigt ist.

Zwei Details führen oft zu Fehlern. Erstens muss die Vertragsadresse, die Sie beim Hinzufügen eines eigenen Tokens einfügen, die echte sein. Gefälschte Token verwenden denselben Namen und dasselbe Symbol. Prüfen Sie die Adresse auf der Website des Projekts. Zweitens wird die angezeigte Gebühr in ETH berechnet. Das ETH-Guthaben der Wallet muss sie zusätzlich zu dem ETH decken, das Sie senden wollen.

Methode 2: Mit Code senden (ethers.js)

Entwickler, die Transfers automatisieren müssen, können den Vertrag direkt aufrufen. Das ethereum.org-Tutorial zum Senden von Token mit ethers.js zeigt das Grundmuster. Eine separate ethers.js-Anleitung erklärt den wichtigsten Unterschied zu ETH. Die Transaktion sendet keinen Wert. Sie ruft die Funktion transfer des Tokens mit einem Ziel und einem Betrag auf.

So sehen die Schritte aus:

  1. Erstellen Sie einen Provider, der mit einem Ethereum-Node verbunden ist. Das kann Ihr eigener Node oder ein gehosteter Endpunkt sein.
  2. Erstellen Sie einen Signer aus einem privaten Schlüssel oder einer Wallet, die Sie kontrollieren.
  3. Instanziieren Sie den Token-Vertrag mit seiner Adresse und einem minimalen ABI, das transfer, balanceOf und decimals enthält.
  4. Rechnen Sie den Betrag mit den Dezimalstellen des Tokens in Basiseinheiten um.
  5. Rufen Sie transfer(recipient, amount) auf und warten Sie auf den Receipt.

Das ethers.js-Tutorial weist darauf hin, dass die Bibliothek eine EIP-1559-Transaktion ohne manuelle Gas-Einstellungen senden kann. Sie wählt dann ein Gas-Limit und eine Standard-Priority-Fee. Bei Verwendung eines Signers verwaltet sie außerdem den Nonce.

Eine minimale Version mit ethers.js v6 sieht so aus (ethers-Dokumentation):

Dezimalstellen richtig behandeln

Token speichern Beträge als Ganzzahlen. Ein Token mit 18 Dezimalstellen stellt 1,0 Token als 1000000000000000000 Basiseinheiten dar. Das Feld decimals gehört zum Standard, aber verschiedene Token setzen unterschiedliche Werte. Die EIP-20-Spezifikation behandelt es als optionale Metadaten. Lesen Sie decimals deshalb immer aus dem Vertrag aus, statt 18 anzunehmen. Ein fest codierter falscher Wert sendet einen Betrag, der um Größenordnungen abweicht.

Dem Rückgabewert nicht blind vertrauen

Der Standard sagt, dass transfer einen booleschen Wert zurückgibt. Nicht jeder Token in freier Wildbahn verhält sich so. Manche geben nichts zurück, andere scheitern auf unerwartete Weise. Das IERC20-Interface von OpenZeppelin ist die Referenz für den Standard.

Die SafeERC20-Bibliothek von OpenZeppelin kapselt Aufrufe, damit ungewöhnliche Token Ihre Logik nicht brechen. Wenn Ihr Smart Contract Token bewegt, nutzen Sie sie. Wenn Ihr Backend Token sendet, prüfen Sie den Status im Transaktions-Receipt und das ausgesandte Transfer-Event. Nehmen Sie keinen Erfolg einfach an.

Gas-Limits

Ein gewöhnlicher ETH-Transfer nutzt laut MetaMask-Anleitung ein Gas-Limit von 21.000. Ein Token-Transfer ist ein Vertragsaufruf und braucht mehr. Schätzen Sie das Gas vor jedem Senden mit der Schätzfunktion Ihrer Bibliothek, statt eine Zahl fest zu codieren. Die Kosten hängen vom Vertrags-Code des Tokens und vom Stand der beteiligten Salden ab.

Methode 3: Über eine REST-API senden

Der Code-Pfad von oben ist für ein Skript in Ordnung. In einem Produkt wird er zu einer Liste von Aufgaben: Node-Zugang betreiben oder mieten, Schlüssel verwalten und Nonces nachverfolgen, damit parallele Sendungen nicht kollidieren. Außerdem gehören dazu Gas schätzen, hängende Transaktionen erneut senden, Logs decodieren, um zu erfahren, ob eine Zahlung angekommen ist, und das alles pro Chain wiederholen.

Eine einheitliche API nimmt Ihrem Team diese Schicht ab. Mit Chaingateway erstellen Sie Wallets, senden Token und lesen decodierte Transaktionsdaten über einfache REST-Aufrufe. Sie brauchen web3.js oder ethers.js in Ihrem Stack nicht, und Sie betreiben keine Nodes. Unsere Ethereum-API-Seite zeigt, wie das Senden von ERC-20-Token über REST funktioniert.

Die OpenAPI-Definition (/openapi.yaml) verlangt from, contractaddress, to und amount sowie password oder privatekey. Die Gas-Felder sind optional.

X-Network: testnet führt die Anfrage auf Sepolia aus. Der amount ist ein Dezimalbetrag des Tokens. Sie müssen ihn also nicht selbst in Basiseinheiten umrechnen.

Dasselbe Vorgehen funktioniert für Polygon, BNB Smart Chain und Arbitrum. Tron und Solana haben eigene Token-Endpunkte. Falls Sie später Tron-USDT hinzufügen, lesen Sie unseren Beitrag TRC10 vs. TRC20. Für BNB-Chain-Adressen finden Sie den BEP20-Adressleitfaden.

Wie gehen ERC-20-Transfers schief?

Token an einen Vertrag senden

Die Funktion transfer ist nicht für Einzahlungen in Smart Contracts gedacht. Hat ein Vertrag keine Logik, um auf eingehende Token zu reagieren, liegen sie in seinem Guthaben ohne Weg hinaus. Die ethereum.org-Seite zu ERC-20 beschreibt dieses Risiko, auch für Token, die an den Vertrag des Tokens selbst gesendet werden.

Sie nennt, dass bis zum 20. Juni 2024 auf diese Weise ERC-20-Token im Wert von mindestens 83,7 Millionen US-Dollar verloren gingen. Wenn Sie Verträge schreiben, fügen Sie eine Funktion hinzu, mit der Sie versehentlich gesendete Token zurückholen können. Braucht ein Vertrag Token von einem Nutzer, ist das Standardmuster so: Der Nutzer ruft approve für den Vertrag auf, danach ruft der Vertrag transferFrom auf.

Null ETH für Gas

Die Transaktion scheitert, wenn der Absender keine native Währung hat, egal wie viele Token in der Wallet liegen. Produktteams entdecken das oft spät. Ein Nutzer erhält Token, will sie bewegen und kann es nicht. Sie können die Wallet mit einer kleinen Menge ETH aufladen. Oder Sie gestalten das Design mit signierten Autorisierungen so, dass es nicht nötig ist.

Falsches Netzwerk oder falsche Adresse

Blockchains machen Transaktionen nicht rückgängig. Prüfen Sie Netzwerk und Adresse, bevor Sie bestätigen. Machen Sie bei allem Neuen einen kleinen Testtransfer.

Token mit dem Netzwerk verwechseln

USDT gibt es zum Beispiel auf mehreren Chains. Wenn jemand sagt, er halte USDT, fragen Sie, in welchem Netzwerk. Die Adresse kann auf jeder Chain gleich aussehen. Die Mittel liegen aber nur auf einer Chain.

Kann ich Token senden, ohne ETH zu halten?

Eine wachsende Option beim Onboarding ist, dass der Nutzer eine Nachricht signiert und jemand anderes die Transaktion absendet und das Gas bezahlt. EIP-3009, Transfer With Authorization, definiert Funktionen, mit denen ein Inhaber die Gas-Zahlung delegieren und Transfers über EIP-712-Signaturen ausführen lassen kann. Das unterstützen nur Token, deren Verträge es implementieren. Prüfen Sie das, bevor Sie einen Ablauf darauf aufbauen. Für ein Startup kann das die Hürde beseitigen, vor dem ersten Transfer ETH beschaffen zu müssen.

Warum sollten Sie einen Transfer als Workflow betrachten?

Der Aufruf transfer selbst ist an einem Nachmittag geschrieben. Die Zeit geht in alles drumherum: wissen, wann eine Zahlung eingegangen ist, eine fehlgeschlagene oder hängende Transaktion behandeln, Gebühren schätzen und Schlüssel sicher aufbewahren. Ein Auszahlungsablauf ohne Bestätigungs-Events zwingt Sie zum Polling. Ein Einzahlungsablauf ohne decodierte Daten zwingt Sie, rohe Logs zu parsen.

Beginnen Sie mit einem kleinen Transfer in einem Testnetz. Prüfen Sie Dezimalstellen und Receipts, abonnieren Sie Events für die Bestätigung und skalieren Sie erst dann das Volumen.

Kann ich Transfers mit Chaingateway automatisieren?

Ja. Für Auszahlungen, Abhebungen oder Einzahlungen innerhalb einer App nutzen Sie die Blockchain-API mit Webhooks, die Sie benachrichtigen, wenn Zahlungen eingehen. Webhooks werden nicht automatisch wiederholt. Listen Sie fehlgeschlagene Benachrichtigungen mit GET /api/v2/ethereum/webhooks/notifications/failed auf und senden Sie sie über den Retry-Endpunkt erneut. Die Tarife auf der Preisseite beginnen bei 49 € pro Monat (Plus). Jeder Tarif startet mit einer siebentägigen kostenlosen Testphase.

Wie bestätigen Sie, dass der Transfer funktioniert hat?

Eine Transaktion abzusenden ist nicht dasselbe wie eine abgeschlossene Zahlung. Nach dem Senden gehen Sie so vor:

  1. Speichern Sie den Transaktions-Hash sofort.
  2. Prüfen Sie den Status im Receipt. Eine in einen Block aufgenommene Transaktion kann trotzdem fehlgeschlagen sein.
  3. Suchen Sie das Transfer-Event des Token-Vertrags mit dem erwarteten Absender, Empfänger und Betrag. Das Event gehört zum ERC-20-Interface.
  4. Warten Sie auf so viele Bestätigungen, wie Ihre Risikorichtlinie verlangt, bevor Sie Waren freigeben oder ein Guthaben gutschreiben.
  5. Gleichen Sie regelmäßig mit balanceOf ab, um alles zu finden, was Ihr Listener übersehen hat.

Polling funktioniert für ein kleines Skript. Ein Abo auf Benachrichtigungen bedeutet dagegen, dass Ihr System auf Events reagiert, statt wiederholt nachzufragen.
