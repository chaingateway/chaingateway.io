Chaingateway Developer Portal and API Docs

The Chaingateway developer portal documents a REST API for creating addresses, sending transactions, reading balances and receiving webhooks on Ethereum, TRON, BNB Smart Chain, Bitcoin, Polygon, Arbitrum and Solana. Start with the quickstart: you create an API key, send one request and switch between mainnet and testnet with a single header.

What can I do with the Chaingateway API?

Section titled “What can I do with the Chaingateway API?”

You can manage wallets, send native coins and tokens, read blockchain data and subscribe to payment notifications through one REST interface. The OpenAPI file lists more than 200 operations. They are grouped per chain, and the same pattern repeats across the EVM chains.

TaskTypical endpointChains
Create a wallet addressPOST /api/v2/{chain}/addressesEthereum, BSC, Polygon, Arbitrum, TRON, Solana
Create a Bitcoin wallet and its addressesPOST /api/v2/bitcoin/walletsBitcoin
Send native coinsPOST /api/v2/{chain}/transactionsall seven
Send tokensPOST /api/v2/{chain}/transactions/erc20, /bep20, /trc20, /SPLall except Bitcoin
Read balances and blocksGET /api/v2/{chain}/balances/{address}all seven
Get notified about paymentsPOST /api/v2/{chain}/webhooksall except Solana
Read a market priceGET /api/v2/market/price/{crypto}/{fiat}chain independent

Solana has no webhook endpoints, so deposits on Solana have to be detected by reading balances or transactions. Wallets are non-custodial: you either choose a password that protects the stored key, or you receive the private key in the response and keep it yourself. Wallet Management explains both modes.

How do I make my first request?

Section titled “How do I make my first request?”

Create an API key in the dashboard, then send it as a Bearer token in the Authorization header. A new account starts with a 7-day free trial, no card and no identity check is needed to begin. The request below reads the latest Ethereum block number.

A request without a valid token returns HTTP 401 with the body {"message":"Unauthenticated."}. To run the same call against the test network, add the header X-Network: testnet. Leave the header out, or set it to mainnet, to use the main network. The Quickstart walks through account setup, headers and a POST request in four languages.

Which networks does the API support?

Section titled “Which networks does the API support?”

Seven blockchains are available, each with a mainnet and a testnet. The testnets are Sepolia for Ethereum, Nile for TRON, the BNB Smart Chain testnet, Bitcoin testnet3, Amoy for Polygon, Arbitrum Sepolia and Solana devnet. Supported Networks lists every network with the matching X-Network value and explains the two header values.

Where do I find the full API reference?

Section titled “Where do I find the full API reference?”

The interactive reference lives at chaingateway.io/docs. It is generated from the same openapi.yaml file that you can import into Postman, Insomnia or a code generator. Each operation lists its parameters, the validation rules for addresses and the example responses, including the error bodies.

Responses share one JSON envelope with the fields status, ok and message. Successful calls add data, failed validation adds an errors object. The FAQ shows examples of both.

What does a response look like?

Section titled “What does a response look like?”

Every endpoint answers with JSON. A successful call returns ok: true together with the HTTP status and a data field. The next example is the response of GET /api/v2/ethereum/gasprice.

A failed validation returns status 422 and names each field that was rejected. The same envelope carries blockchain errors, for example insufficient funds for gas. A wrong wallet password returns 401 with the message Wrong password provided. Write your client so that it checks ok first and logs message and errors when it is false.

Sources

Section titled “Sources”

The HTTP and token conventions used in these docs are defined by public standards:

  • RFC 9110, HTTP Semantics for methods, status codes and headers.
  • RFC 6750, Bearer Token Usage for the Authorization: Bearer header.
  • RFC 8259, The JSON Data Interchange Format for request and response bodies.
  • Ethereum developer documentation and TRON developer documentation for the chains behind the endpoints.
