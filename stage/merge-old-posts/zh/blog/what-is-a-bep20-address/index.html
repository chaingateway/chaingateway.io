什么是 BEP20 地址？格式、EIP-55 校验和与 BSC 充值地址

什么是 BEP20 地址，0x 格式与 EIP-55 校验和如何运作，BEP-2 为何不同，以及如何通过 API 创建 BSC 充值地址。文章还包含 JavaScript 与 PHP 校验代码、MetaMask 与 Trust Wallet 的查找步骤，以及在 BscScan 上核对地址和代币的方法。

章节
C
Chaingateway Team
区块链专家

审核： Maurice Sobiera

BEP20 地址是 BNB 智能链（BSC，原名币安智能链）上的账户地址。它以 0x 开头，长 42 个字符，格式与以太坊地址相同，因此以太坊地址的代码同样适用。仍需注意两个陷阱：较早的 BEP-2 标准，以及在每条 EVM 链上完全相同的地址。

本指南涵盖地址格式、EIP-55 校验和、校验代码、钱包操作步骤，以及如何通过 API 创建 BSC 地址。

BEP20 地址长什么样？

BEP20 地址是 0x 后跟 40 个十六进制字符，这 40 个字符编码了 20 字节（160 位）：

有三项检查可以判断一个字符串能否作为地址：

  • 以前缀 0x 开头。
  • 前缀之后恰好是 40 个字符。
  • 这 40 个字符都是十六进制数字：0–9、a–f 或 A–F。

代币没有单独的地址类型。USDT、USDC、CAKE 等 BEP20 代币与持有 BNB 的，是同一种 42 字符的账户地址。您的币安智能链钱包地址（用于 BNB）和用于代币的 BEP20 地址，是同一个字符串。

这 20 字节从哪里来？账户起始于 secp256k1 曲线上的一个随机私钥，这与比特币和以太坊使用的曲线相同。由该私钥推导出的公钥经 Keccak-256 哈希，哈希结果的最后 20 字节即成为地址。无需在任何地方注册。地址在数学计算完成的那一刻即已存在，即使链上尚未出现过一笔来自它的交易。

为什么 BEP20 地址看起来像以太坊地址？

因为 BSC 兼容 EVM：它运行以太坊虚拟机，因此采用以太坊的账户模型、密钥派生和地址格式。BNB 智能链文档把它描述为兼容 EVM，并支持现有的以太坊工具。BEP-20 是 BSC 的代币标准，派生自以太坊的 ERC-20，函数名（transfer、balanceOf、approve）相同。

区分两条网络的技术标识是链 ID：BSC 主网为 56，以太坊主网为 1，BSC 测试网为 97，列于 BSC RPC 文档。根据 EIP-155，链 ID 被纳入每笔交易的签名，从而防止为一条链签名的交易在另一条链上被重放。地址本身完全不携带链信息。您无法通过看 0x71C7...976F 来判断其所有者是在 BSC、以太坊，还是两者上使用它。

BEP-20 与 ERC-20、TRC-20 并列对比

稳定币支付通过三个主要网络到达企业，许多资金丢失的支持工单都涉及其中两者被混淆。下表列出了差异，数据来自截至 2026 年 11 月所引用的文档：

资料来源：BSC 的出块时间与最终性见 BEP-619 提案；以太坊的时隙与 epoch 见 ethereum.org；TRON 见 TRON 共识文档。

其中两行值得仔细看。BEP-20 与 ERC-20 的地址行完全相同，因为 BSC 在校验和算法层面都照搬了以太坊的格式。接受其中一种的验证器也会接受另一种，并且无法判断用户指的是哪条网络，只有周围的上下文可以提供线索。TRC-20 是例外。TRON 地址会立即未通过 EVM 校验，这听起来像是不便，实际上却是一种保护：粘贴错误的地址仅凭格式就会被拒绝，在任何资金移动之前即可发现。

速度数字的有效期很短，格式行则不然。BSC 在八个月内两次缩短了出块间隔。BEP-524 通过 Maxwell 硬分叉将其从 1.5 秒降至 0.75 秒，计划于 2025 年 6 月 30 日生效，见 v1.5.16 发布说明。BEP-619 通过 Fermi 硬分叉将其从 0.75 秒降至 0.45 秒，计划于 2026 年 1 月 14 日生效，见 v1.6.4 发布说明。自各链上线以来，这三种地址格式从未改变。今天编写的校验代码能经受每一次分叉，而手续费表则需要持续维护。

手续费是另一个会变动的数字。以太坊和 BSC 以各自的原生代币收取 Gas 费。根据 TVM 与 EVM 文档，TRON 没有优先费竞价：每笔交易支付相同的固定能量价格。在决定提供哪些充值网络之前，请在每条网络上测量一笔真实转账的手续费。TRON 一侧的情况，请参阅我们关于 TRC-20 手续费的文章。

什么是 EIP-55 校验和？

EIP-55 校验和是隐藏在地址字母大小写中的一种错误检查。十六进制对大小写不敏感，因此 0xab... 与 0xAB... 指向同一个账户。EIP-55 于 2016 年为以太坊创建，BSC 也在使用，它把这一额外的自由度变成了校验。

规则如下：将地址转为小写（去掉 0x），用 Keccak-256 对其做哈希，然后逐个检查 40 个字符。若哈希结果在某一位置的数字是 8 或更大，则该位置的地址字母写成大写；否则写成小写。数字保持不变。

结果就是钱包和区块浏览器所显示的大小写混合形式。若用户输错了带校验和地址中的一个字符，大小写模式便与哈希不再相符，校验失败，因此在任何资金移动之前即可发现这一错误。全小写的地址在技术上仍然有效，只是不带校验和，您的代码应将其视为未经验证的输入，而不是直接拒绝。

为什么 BEP-2 与 BEP-20 使用不同的地址格式？

因为它们属于两条不同的链。这种混淆曾让用户损失真金白银。币安曾并行运行两条链：

  • BNB Beacon Chain，使用 BEP-2 代币标准，地址以 bnb1 开头
  • BNB 智能链，使用 BEP-20 标准，地址为 0x 格式

向交易所充值 BEP-2 还需要备注字段，而忘记备注是典型的支持工单。那个时代已经结束：币安于 2024 年作为 BNB Chain Fusion 的一部分退役了 Beacon Chain，BEP-2 也随之退役。若某篇教程提到 bnb1 地址或备注，它已经过时。如今，“BNB 地址”和“BSC 地址”在实践中指的都是 0x 格式的 BEP20 地址。

这一名称仍保留在交易所的提现菜单中，网络通常标注为“BSC (BEP20)”或“BNB Smart Chain (BEP20)”。看到这类标签时，目标地址必须是 0x 地址。

一个地址，多条链：为什么网络选择器很重要

因为 BSC 照搬了以太坊的派生方式，同一私钥在以太坊、BSC、Polygon、Arbitrum 以及其他所有 EVM 链上控制的是同一个 0x 地址。这既方便，又危险。

方便之处：拥有 MetaMask 或 Trust Wallet 账户的用户已经有了一个 BEP20 地址。他们只需在钱包设置中添加 BSC 网络，现有地址即可使用。

危险之处：同名代币在不同链上以各自独立的合约存在。BSC 上的 USDT 与以太坊上的 USDT 除了代号之外毫无共同之处。若有人从交易所提现 USDT 时选错了网络，代币会到达正确的地址，却位于错误的链上。可能出现两种结果：

  1. 收款人掌握私钥（自托管钱包）。那么不会有任何损失，他们只需把钱包切换到另一条网络，就能在那里找到代币。
  2. 收款人是交易所或支付处理商的充值地址，而该地址只监控一条网络。那么代币就会停留在无人监控的账户中。有些交易所会收取费用后予以找回，有些则不会。

开发者的实用规则是：展示地址时，始终同时注明网络；入账时，要在您实际入账的那条链上核实到账。仅凭地址字符串本身是存在歧义的，这是设计使然。

如何在 MetaMask、Trust Wallet 和硬件钱包中找到您的 BEP20 地址

每个支持 EVM 的钱包最终都会显示同一样东西，即一个 0x 地址，只是到达该地址的路径略有不同。以下步骤刻意保持通用，因为菜单标签会随应用版本变动。

MetaMask

MetaMask 默认连接到以太坊。要在 BSC 上使用，请添加 BNB 智能链作为网络（链 ID 56，货币为 BNB），RPC 信息可从 BNB Chain 文档获取。您的账户地址位于主界面顶部，单击即可复制。切换网络时地址不会改变。在网络菜单中选择 BSC，改变的是交易的去向，而不是您的身份。

Trust Wallet

在 Trust Wallet 中，选择您预期要收到的资产，例如 BNB 或标有“BEP20”的代币，打开接收页面，应用会以文本和二维码两种形式显示 0x 地址。每个代币旁的网络标签比地址本身更重要：“USDT BEP20”和“USDT ERC20”在您的钱包中对应同一个地址字符串，但它们告诉发送方应使用哪条链，而出错的恰恰是这一部分。

硬件钱包

使用 Ledger 或 Trezor 时，私钥永远不会离开设备，BSC 通过与以太坊相同的 EVM 集成运行。接收流程中有一个值得保留的步骤：设备会在自己的屏幕上显示地址，您在分享之前应将其与电脑上显示的内容进行比对。这一比对可以防御剪贴板恶意软件，此类软件会替换电脑上的地址，却无法触及设备屏幕。

无论使用哪种钱包，复制的字符串都不携带网络信息。将其粘贴到交易所的提现表单中时，旁边的网络下拉菜单才起决定作用，因此请确认它显示的是 BSC 或 BEP20。

一组助记词，多个地址：两分钟看懂 HD 钱包

现代钱包不会保存一堆互不相关的密钥。它们从一个种子派生出所有密钥，遵循三个相互叠加的标准。BIP-39 将 12 或 24 个词典单词转换为种子。BIP-32 从该种子生成一棵确定性的密钥对树，因此同样的词总是生成同样的树。BIP-44 规定哪一分支属于哪种币，并以派生路径的形式书写。

对于以太坊，注册的路径是 m/44'/60'/0'/0/0，其中 60 为币种类型。SLIP-44 注册表为币安智能链列出了单独的币种类型（9006），但遵循以太坊惯例的钱包对每条 EVM 链都使用 60。这就是为什么这类钱包会在 BSC、以太坊、Polygon 和 Arbitrum 上显示完全相同的地址。路径中最后一个数字是索引。将其递增，钱包便会从同一组词派生出第二个地址，然后是第三个，无需新的备份。

由此得出两个结论。在任何 BIP-44 钱包中恢复种子词，都会重建您曾派生过的每一个地址，因此这些词就是备份，而且是全部备份。另外，需要成千上万个充值地址的平台，原则上可以从一个种子全部派生出来，不过生产环境通常是逐个生成密钥并通过 API 注册，因此不存在一个能同时控制所有客户充值的单一秘密。

在 BscScan 上核对地址

BscScan 是 BSC 的区块浏览器，花三十秒在那里查看，就能回答大多数“成功了吗？”的问题。

在搜索框中粘贴任何地址，即可进入其账户页面：BNB 余额、代币持仓和交易列表。对于您刚创建的充值地址，页面为空是正常的。地址只是数学上的存在；只有在第一笔转账涉及它之后，浏览器才有内容可显示。

留意页面顶部附近的标签。带有“Contract”标签的账户是智能合约，包括代币合约。资金应转入普通地址，因此，如果对方要求您向某个合约地址付款，请先停下来，问清原因。

第三个用途是代币验证。任何人都可以在 BSC 上部署一个名为“USDT”的代币，搜索结果会把仿冒品与真品并列显示。代号什么也证明不了，合约地址才能证明。请将它与代币发行方公布的地址进行比对，然后再查看代币页面上的持有人数和已验证的源代码。仿冒品很少能把这些伪造得很逼真。

完成一笔测试交易后，请改为搜索交易哈希。详情页会显示发送方、接收方、代币合约和金额，这些信息共同确认资金确实按您的意图、在您预期的链上到达了目的地。

发送前：避免代价高昂错误的简短流程

三个习惯就能覆盖 BEP20 转账出错的几乎所有情形。

让网络标签与地址的年代相符。当前的一切都是“BSC (BEP20)”配以 0x 目标地址。若某份指南、表单或交易对手提到 bnb1 地址或充值备注，那说的是 BEP-2，它已随 2024 年 Beacon Chain 的退役而退出。应将此类说明视为过时，而非另一种可选方案。

提现表单要读两遍：一遍看地址，一遍看网络下拉菜单。地址字段校验格式，下拉菜单决定链，而没有任何校验器能发现“地址正确、网络错误”。这正是上文所述的失败模式，它发生在发送端，因此您可以在发送端加以防范。

对每个新地址先发送一笔测试金额。在 BSC 上，这一纪律只需一笔小额转账和短暂等待，几乎没有理由不这样做。在 BscScan 上确认测试到账后，再发送剩余的金额。处理付款的团队会把这一习惯制度化：新的付款地址只有在一笔已确认的测试转账之后才会加入白名单。

通过 API 创建 BSC 地址

若您经营商店、SaaS 产品或类似交易所的平台，您需要的地址不止一个：通常每位客户需要一个充值地址，以便区分不同的入账付款。在钱包应用中手动完成这一工作，用户超过少数几个就无法扩展。

每位客户一个充值地址，并配合 Webhook

地址只是付款流程的一半。另一半是在不自行轮询链的情况下，获知款项已经到账。模式如下：

  1. 当客户开始付款时，为其分配一个专用的 BSC 地址，并在您的数据库中保存地址与客户的对应关系。
  2. 为该地址注册一个 Webhook。当 BEP20 转账到达该地址时，Chaingateway 会以交易详情调用您的端点。
  3. 校验 Webhook 的 HMAC 签名，然后在您自己的系统中为客户入账。

Webhook 投递均带有 HMAC 签名，因此您可以拒绝伪造的调用。服务器错过的投递也不会丢失：GET /api/v2/bsc/webhooks/notifications/failed 会列出它们，POST /api/v2/bsc/webhooks/notifications/{id}/retry 可以重新发送某一条。若您的服务器曾经宕机，GET /api/v2/bsc/webhooks/notifications 会返回过去的通知，因此故障之后的对账只需一次 API 调用。包括签名校验在内的完整设置，见 Webhook 指南。

同样的模式也适用于 TRON，尽管其地址格式完全不同。该方面请参阅什么是 TRC20 地址？。

常见问题

BEP20 地址与以太坊地址是同一种地址吗？

格式相同：0x 加 40 个十六进制字符，以相同方式从 secp256k1 密钥派生而来。同一个私钥甚至可以在两条网络上控制同一个地址字符串。但余额按链分别计算。在 BSC 上持有 100 USDT，并不能说明您在以太坊上的余额。

如何获得 BEP20 钱包地址？

个人使用时，在任何支持 BSC 的钱包中创建账户即可（例如已添加 BSC 网络的 MetaMask、Trust Wallet，或硬件钱包），钱包会显示您的 0x 地址。若应用需要大量地址，请以编程方式生成密钥，并通过 API 注册，例如使用 POST /api/v2/bsc/addresses/import。

如果把 BEP20 代币发送到以太坊地址会怎样？

交易会成功，因为每个以太坊格式的地址在 BSC 上同样有效。代币会到达 BSC 上的该地址。若所有者掌握私钥，他们可以在钱包中添加 BSC 网络并访问这些代币。若这是一个只监控以太坊的交易所充值地址，代币就会滞留，您只能依赖该交易所的找回流程。

BEP-2 与 BEP-20 有什么区别？

BEP-2 是已停用的 BNB Beacon Chain 的代币标准，使用 bnb1... 地址并带有备注字段。BEP-20 是 BNB 智能链上类似 ERC-20 的标准，使用 0x... 地址。自 2024 年 Beacon Chain 关闭以来，BEP-20 实际上是唯一有意义的标准。

BEP20 地址区分大小写吗？

不区分。同一组十六进制数字，无论大写还是小写，都指向同一个账户。您看到的大小写混合形式就是 EIP-55 校验和：它把错误检查编码进字母的大小写，使钱包能够在发送前发现输入错误。

接收 BEP20 代币需要 BNB 吗？

不需要。发送方支付 Gas 费，因此接收不需要您付出任何费用。当您想把代币转出时，才需要 BNB：BEP20 转账消耗的 Gas 比普通的 21,000 Gas BNB 转账更多，以 BNB 支付，因此手续费等于所用 Gas 乘以当前 Gas 价格。持有 USDT 但 BNB 为零的钱包是典型的支持案例；这些代币会一直静止，直到有少量 BNB 到账以支付手续费。

一笔 BEP20 转账需要多长时间？

自 2026 年 1 月的 Fermi 硬分叉以来，BSC 的出块间隔为 0.45 秒；当快速最终性生效时，BEP-619 使最终确认约为 1.1 秒。钱包之间的转账几秒内即可完成。交易所会在此之上叠加自己的确认要求，因此充值入账可能晚于链上的最终确认。

如何确认 BSC 上的代币是真的？

检查合约地址，而不是名称或图标。将 BscScan 上显示的合约地址与发行方在官方网站上公布的地址进行比对，并把持有人数和已验证的源代码作为辅助依据。一个代号正确、只有几十个持有人、代码未经验证的代币，就是仿冒品。
