Portail développeur Chaingateway

Le portail développeur Chaingateway documente une API REST pour créer des adresses, envoyer des transactions, lire des soldes et recevoir des webhooks sur Ethereum, TRON, BNB Smart Chain, Bitcoin, Polygon, Arbitrum et Solana. Commencez par le démarrage rapide : vous créez une clé API, envoyez une requête et passez du mainnet au testnet avec un seul en-tête.

Que puis-je faire avec l’API Chaingateway ?

Section intitulée « Que puis-je faire avec l’API Chaingateway ? »

Vous pouvez gérer des wallets, envoyer des coins natifs et des tokens, lire des données blockchain et vous abonner aux notifications de paiement via une seule interface REST. Le fichier OpenAPI répertorie plus de 200 opérations. Elles sont regroupées par chaîne, et le même schéma se répète sur les chaînes EVM.

TâcheEndpoint typiqueChaînes
Créer une adresse de walletPOST /api/v2/{chain}/addressesEthereum, BSC, Polygon, Arbitrum, TRON, Solana
Créer un wallet Bitcoin et ses adressesPOST /api/v2/bitcoin/walletsBitcoin
Envoyer des coins natifsPOST /api/v2/{chain}/transactionsles sept
Envoyer des tokensPOST /api/v2/{chain}/transactions/erc20, /bep20, /trc20, /SPLtoutes sauf Bitcoin
Lire les soldes et les blocsGET /api/v2/{chain}/balances/{address}les sept
Être notifié des paiementsPOST /api/v2/{chain}/webhookstoutes sauf Solana
Lire un prix de marchéGET /api/v2/market/price/{crypto}/{fiat}indépendant de la chaîne

Solana ne dispose d’aucun endpoint de webhook : les dépôts sur Solana doivent donc être détectés en lisant les soldes ou les transactions. Les wallets sont non custodiaux : soit vous choisissez un mot de passe qui protège la clé stockée, soit vous recevez la clé privée dans la réponse et la conservez vous-même. Gestion des wallets explique les deux modes.

Comment effectuer ma première requête ?

Section intitulée « Comment effectuer ma première requête ? »

Créez une clé API dans le dashboard, puis envoyez-la comme token Bearer dans l’en-tête Authorization. Un nouveau compte démarre avec un essai gratuit de 7 jours, sans carte bancaire ni vérification d’identité. La requête ci-dessous lit le numéro du dernier bloc Ethereum.

Une requête sans token valide renvoie HTTP 401 avec le corps {"message":"Unauthenticated."}. Pour exécuter le même appel sur le réseau de test, ajoutez l’en-tête X-Network: testnet. Omettez l’en-tête, ou réglez-le sur mainnet, pour utiliser le réseau principal. Le démarrage rapide détaille la création du compte, les en-têtes et une requête POST dans quatre langages.

Quels réseaux l’API prend-elle en charge ?

Section intitulée « Quels réseaux l’API prend-elle en charge ? »

Sept blockchains sont disponibles, chacune avec un mainnet et un testnet. Les testnets sont Sepolia pour Ethereum, Nile pour TRON, le testnet de BNB Smart Chain, Bitcoin testnet3, Amoy pour Polygon, Arbitrum Sepolia et le devnet de Solana. Réseaux pris en charge liste tous les réseaux avec la valeur X-Network correspondante et explique les deux valeurs de l’en-tête.

Où trouver la référence complète de l’API ?

Section intitulée « Où trouver la référence complète de l’API ? »

La référence interactive se trouve sur chaingateway.io/docs. Elle est générée à partir du même fichier openapi.yaml que vous pouvez importer dans Postman, Insomnia ou un générateur de code. Chaque opération indique ses paramètres, les règles de validation des adresses et des exemples de réponses, y compris les corps d’erreur.

Les réponses partagent une même enveloppe JSON avec les champs status, ok et message. Les appels réussis ajoutent data, une validation échouée ajoute un objet errors. La FAQ montre des exemples des deux cas.

À quoi ressemble une réponse ?

Section intitulée « À quoi ressemble une réponse ? »

Chaque endpoint répond en JSON. Un appel réussi renvoie ok: true avec le statut HTTP et un champ data. L’exemple suivant est la réponse de GET /api/v2/ethereum/gasprice.

Une validation échouée renvoie le statut 422 et nomme chaque champ rejeté. La même enveloppe porte les erreurs blockchain, par exemple des fonds insuffisants pour le gas. Un mauvais mot de passe de wallet renvoie 401 avec le message Wrong password provided. Écrivez votre client de façon à vérifier d’abord ok, puis à journaliser message et errors lorsque la valeur est false.

Quel guide lire ensuite ?

Section intitulée « Quel guide lire ensuite ? »

Choisissez la page qui correspond à la tâche en cours :

  • Pour stocker les clés en sécurité, lisez Gestion des wallets.
  • Pour détecter les paiements entrants, lisez Webhooks, puis Sécurité des webhooks.
  • Pour envoyer des coins, suivez Créer des transactions et Créer des transactions de tokens.
  • Pour payer les frais TRON sans détenir de TRX, lisez Sponsoriser les frais TRC20.

Sources

Section intitulée « Sources »

Les conventions HTTP et de tokens utilisées dans cette documentation sont définies par des normes publiques :

  • RFC 9110, HTTP Semantics pour les méthodes, les codes de statut et les en-têtes.
  • RFC 6750, Bearer Token Usage pour l’en-tête Authorization: Bearer.
  • RFC 8259, The JSON Data Interchange Format pour les corps de requête et de réponse.
  • Documentation développeur Ethereum et documentation développeur TRON pour les chaînes derrière les endpoints.
