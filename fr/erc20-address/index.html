Une adresse ERC20 est le même format d'adresse préfixé 0x, à 42 caractères, qu'Ethereum utilise pour chaque compte — elle devient une « adresse ERC-20 » dans le contexte dès que ce compte détient des tokens conformes au standard ERC-20. Comme le format est partagé sur toutes les chaînes EVM, la même erc20 address que vous utilisez sur Ethereum fonctionne sans changement sur Polygon et Arbitrum, même si les tokens et les soldes à cette adresse sont spécifiques à chaque chaîne. Cette page couvre le format, l'appel balanceOf qui lit un solde de token, et la création d'adresses via une API.

Le standard ERC-20, en bref

ERC-20 est le standard de token fongible d'Ethereum : un petit ensemble de fonctions — transfer, approve, balanceOf et quelques autres — que tout contrat de token conforme implémente, ce qui permet aux wallets et aux plateformes d'échange de supporter de nouveaux tokens ERC-20 sans travail d'intégration spécifique par token. La mécanique complète est détaillée dans l'article sur le standard de token ERC20 sur le blog ; cette page se concentre sur le volet adresse : ce qu'est une erc20 address et comment y travailler par programmation.

balanceOf : comment un solde ERC-20 est réellement lu

Un solde de token ERC-20 n'est pas stocké à l'adresse elle-même — il est stocké dans le smart contract du token, dans un mapping indexé par adresse. balanceOf(address) est la fonction standard en lecture seule que tout contrat ERC-20 expose pour consulter cette valeur. L'appeler directement signifie encoder un eth_call JSON-RPC brut contre le contrat du token et décoder le hex retourné. L'API Chaingateway effectue ce décodage pour vous : les endpoints de solde et d'historique de transactions retournent des nombres simples, si bien que « erc20 balanceof » cesse d'être un problème de RPC brut pour devenir une réponse API normale.

La même adresse sur Polygon et Arbitrum

Polygon et Arbitrum sont tous deux compatibles EVM, si bien qu'une adresse Polygon et une adresse Arbitrum utilisent le format 0x identique à une adresse Ethereum, et peuvent même être la toute même adresse si elle est dérivée de la même clé. C'est aussi pourquoi les tokens Polygon sont des tokens ERC-20 dans tous les sens fonctionnels — Polygon est-il un réseau de token ERC-20, pas un standard d'adresse différent — POL et les tokens natifs de Polygon implémentent la même interface que les tokens Ethereum. Les contrats de token diffèrent selon la chaîne même quand le format d'adresse ne diffère pas ; un token déployé sur Ethereum nécessite un déploiement séparé (ou un bridge) pour exister sur Polygon.

ERC-721 et ERC-721A : un standard différent, le même format d'adresse

ERC-721 est le standard de token non fongible d'Ethereum — chaque ID de token est unique plutôt qu'interchangeable, contrairement aux soldes fongibles d'ERC-20. ERC-721A est une implémentation largement utilisée et optimisée en gas de la même interface ERC-721, populaire pour les collections NFT mintées par lots ; elle change la façon dont le contrat stocke les données en interne, pas l'apparence de l'adresse d'un détenteur. Les deux utilisent la même adresse 0x de type erc20 pour la propriété. L'article sur le standard de token ERC721 couvre le volet NFT en profondeur.
