Envoyer des transactions ETH, BNB, TRX, BTC

Pour envoyer un coin natif, vous transmettez l’émetteur, le destinataire, le montant et un secret de signature à POST /api/v2/{chain}/transactions. Chaingateway signe et diffuse la transaction, puis renvoie son identifiant (txid). Le secret est le password du wallet pour une adresse protégée, ou la privatekey pour une adresse sans mot de passe. Ce tutoriel couvre ETH, BNB, MATIC, TRX, BTC et SOL.

Les tokens comme USDT utilisent d’autres endpoints, décrits dans Créer des transactions de tokens. Il vous faut un token API et une adresse approvisionnée, voir le Démarrage rapide et Créer des adresses.

Comment envoyer de l’ETH, du BNB ou du MATIC ?

Section intitulée « Comment envoyer de l’ETH, du BNB ou du MATIC ? »

Utilisez l’endpoint de la chaîne : /ethereum, /bsc, /polygon ou /arbitrum. Le corps pour les chaînes EVM comporte trois champs obligatoires et un secret de signature.

ChampObligatoireSignification
fromouiAdresse de l’émetteur, validée comme 40 caractères hexadécimaux avec un 0x facultatif.
toouiAdresse du destinataire, même format.
amountouiLe montant à envoyer.
passwordl’un des deuxMot de passe du wallet. Obligatoire quand privatekey est absent.
privatekeyl’un des deuxClé privée de l’émetteur, pour les adresses créées sans mot de passe.
gas, gasprice, maxPriorityFeePerGas, maxFeePerGas, nonce, datanonParamètres de transaction facultatifs.

Envoyez d’abord un petit montant sur le testnet, avec l’en-tête X-Network: testnet, et comparez la variation du solde avant de déplacer de vrais fonds. L’unité de amount suit la référence API de l’endpoint, vérifiez-la donc à cet endroit. L’en-tête d’autorisation porte votre token : Authorization: Bearer YOUR_API_TOKEN.

Note

Utilisation pour d’autres blockchains et réseaux L’exemple utilise /ethereum dans la route. Remplacez-le par /bsc, /polygon ou /arbitrum pour les autres chaînes EVM. L’en-tête X-Network: testnet fait passer une requête sur le réseau de test. Il n’existe pas d’hôte testnet distinct.

Comment envoyer des TRX ?

Section intitulée « Comment envoyer des TRX ? »

POST /api/v2/tron/transactions accepte from, to et amount, plus password ou privatekey. Les adresses Tron doivent correspondre au motif T suivi de 33 caractères alphanumériques. L’émetteur doit détenir assez de TRX pour le montant et pour les ressources réseau que le transfert consomme, comme le décrit le modèle de ressources de TRON.

La réponse a la même forme que la réponse EVM ci-dessus, avec le hash de la transaction dans data.txid. Si vous signez les transactions dans votre propre code, POST /api/v2/tron/transactions/build renvoie une transaction non signée et POST /api/v2/tron/transactions/broadcast accepte la transaction signée dans le champ signed_transaction.

Comment envoyer des BTC ?

Section intitulée « Comment envoyer des BTC ? »

Bitcoin envoie depuis un wallet, pas depuis une adresse isolée. POST /api/v2/bitcoin/transactions exige to, amount, walletname, password et speed. Le champ speed vaut fast, medium ou slow et fixe le niveau des frais. Le champ facultatif subtractfee prélève les frais sur le montant au lieu de les ajouter en plus.

Les adresses Bitcoin sont validées avec le motif (bc1|tb1|[13]) suivi de 25 à 39 caractères, ce qui accepte les formats mainnet et testnet. Le guide développeur Bitcoin sur les transactions explique les entrées, les sorties et les frais.

Comment envoyer des SOL ?

Section intitulée « Comment envoyer des SOL ? »

POST /api/v2/solana/transactions accepte from, to, amount et la privatekey de l’émetteur. Le fichier OpenAPI indique les quatre comme obligatoires et ne prévoit aucun mode par mot de passe pour Solana. Les tokens SPL utilisent POST /api/v2/solana/transactions/SPL avec le champ supplémentaire contractaddress, qui contient l’adresse mint du token.

Comment définir le gas et les frais sur les chaînes EVM ?

Section intitulée « Comment définir le gas et les frais sur les chaînes EVM ? »

Vous n’y êtes pas obligé, car gas, gasprice, maxPriorityFeePerGas et maxFeePerGas sont facultatifs. Pour les fixer vous-même, lisez le prix actuel avec GET /api/v2/ethereum/gasprice, qui renvoie dans data une valeur comme {"gasPrice":"12.28"}. Les deux champs max correspondent aux paramètres de frais de l’EIP-1559. La documentation Ethereum sur les transactions liste tous les champs d’une transaction, y compris nonce.

Comment vérifier que la transaction est passée ?

Section intitulée « Comment vérifier que la transaction est passée ? »

Utilisez le txid de la réponse. GET /api/v2/ethereum/transactions/{txid} renvoie la transaction, et GET /api/v2/ethereum/transactions/{txid}/decoded la renvoie avec les données d’entrée décodées. Un hash de transaction inconnu du nœud donne le statut 422 et le message transaction not found. Pour être prévenu de l’arrivée de fonds, créez un webhook plutôt que d’interroger l’API en boucle.

Quelles erreurs puis-je rencontrer ?

Section intitulée « Quelles erreurs puis-je rencontrer ? »

Les erreurs utilisent la même enveloppe que les appels réussis, avec ok à false.

StatutMessageCause
401Wrong password providedLe password ne correspond pas à l’adresse.
422insufficient funds for gas * price + value: ...Le solde ne couvre pas le montant plus les frais.
422Data validation failedUn champ manque ou a un mauvais format. L’objet errors le nomme.
422Error: The wallet passphrase entered was incorrect.Bitcoin : le password du wallet est incorrect.

Informations importantes

Section intitulée « Informations importantes »

Chaingateway ne stocke pas vos mots de passe ni les clés privées des adresses non protégées. Si vous les perdez, personne ne peut récupérer les fonds de l’adresse. Conservez les deux dans un coffre à secrets, jamais dans du code côté client.
