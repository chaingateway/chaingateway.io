在 Laravel 中接收加密货币付款（Tron）

用 Laravel 搭建接收 TRX 与 TRC20 代币付款的网关：每个付款会话一个地址、Chaingateway Webhook、签名校验与交易验证，并说明失败通知的重试方法。本教程提供完整代码，但仅作演示，不可直接用于生产环境。

审核： Maurice Sobiera

Laravel 加密支付网关为每个付款会话创建一个区块链地址，在该地址上注册 Webhook，并在收到已验证的通知时将会话标记为已付款。本教程借助 Chaingateway API，为 Tron 上的 TRX 和 JST 代币（TRC20）构建这一流程。代码仅为演示，不是生产系统。

同样的模式也适用于比特币、以太坊、BNB 智能链和 Polygon，只需对端点做少量修改。演示代码可在 chaingateway-crypto-payment-demo-laravel 仓库中获取。

请勿在生产环境中使用这段代码。演示代码以明文存储私钥，这在生产环境中绝不能发生。Chaingateway 也可以创建受密码保护的地址，此时您无需存储私钥，只需发送一个 password。

本教程要构建什么？

成果是一个小型支付网关，包含以下部分：

  1. 一个表单，用于以金额和币种（TRX 或 JST）启动一个付款会话。
  2. 为每个会话生成的新钱包地址。
  3. 一个会话页面，显示地址、状态、应付金额和已收到的金额。
  4. 一个 Webhook 端点，负责校验签名、检查交易、更新会话，并可选地将资金转入冷钱包。

如何获取 API 密钥？

您在 Chaingateway 账户面板中创建 API 令牌。登录 app.chaingateway.io，打开用户设置并选择 API Tokens。点击 Create Token，为其命名（例如“Payment Gateway”），然后复制该值。每个请求都以 Bearer 令牌的形式发送它。开发者门户和 API 参考详细描述了各个端点。

您还需要一个配置好数据库的 Laravel 项目。如果从零开始，请遵循 Laravel 安装指南。掌握模型、迁移、控制器和路由的基础知识即可。

第 2 步：如何定义路由？

四条路由覆盖整个流程：付款页面、启动会话、会话视图和 Webhook 接收端。请将它们添加到 routes/web.php。Webhook 路由需要一个名称，因为控制器通过 route('handleWebhook') 构建其 URL。

Laravel 会拒绝没有 CSRF 令牌的 POST 请求，而 Chaingateway 无法发送该令牌。请在 bootstrap/app.php 中将 Webhook 路由排除在外。Laravel CSRF 文档对旧版本描述了相同的设置。

您的 Webhook URL 必须能从公共互联网访问。在本地开发时，请通过隧道暴露开发服务器。

第 4 步：PaymentController 如何工作？

控制器负责创建钱包、注册 Webhook 并处理传入的通知。使用 php artisan make:controller PaymentController 生成它。

创建会话需要两次 API 调用。POST /api/v2/tron/addresses 返回一个新地址，若未设置密码，还会返回其私钥。POST /api/v2/tron/webhooks 为发往该地址的交易注册 Webhook，并在 data.webhook 中返回 Webhook ID。

Webhook 处理程序按顺序执行四件事。它验证 X-Signature 请求头。它按接收地址查找会话。它向 API 请求该交易，并检查 ret[0].contractRet 是否为 SUCCESS。只有在此之后，它才会更新会话。

Pending 检查可以防范重复的通知，当您重新发送失败的通知时，就可能出现重复。您的服务器未接受的通知不会自动重试。它会出现在 GET /api/v2/tron/webhooks/notifications/failed 的失败通知列表中，您可以通过 POST /api/v2/tron/webhooks/notifications/{id}/retry 重新发送。

如何验证 Webhook 签名？

使用您的个人密钥对 txid 计算 HMAC-SHA256，并与 X-Signature 请求头进行比较。该请求头保存的是 Base64 编码的结果。HMAC 的规范见 RFC 2104。上面的 signatureIsValid 方法使用 hash_hmac 实现了这一点，并使用 hash_equals 进行比较，后者耗时恒定。签名文档列出了其他语言中的相同校验方法。

如果没有配置密钥，演示代码会拒绝每一条通知。没有有效签名的请求，可能来自任何知道您 Webhook URL 的人，因此您不应跳过这项检查。

第 6 步：如何测试流程？

先在测试网上测试。使用 php artisan serve 启动服务器，然后按以下步骤操作。

  1. 打开 /payment 并启动一个新会话。
  2. 向会话页面上的钱包地址发送测试网资金。
  3. 等待 Webhook，或自己向 /webhook 发送一条已签名的通知。
  4. 重新加载会话页面，检查状态是否已变更。

要模拟一条通知，请使用 Webhook 文档中的类似负载，并附上有效的 X-Signature 请求头。请记住，交易检查会就 txid 调用 API，因此一个虚构的交易 ID 最终会得到 Failed 状态。

上线生产前还需要增加什么？

在接收真实付款之前，请替换演示中的捷径。

  • 创建带密码的地址，使您的数据库中不存储任何私钥。
  • 只有在达到您的风险政策所要求的确认数之后，才为付款入账。
  • 以代币的最小单位比较金额，并为每种代币核对合约地址。
  • 定期将未完成的会话与 API 进行对账，因为 Webhook 可能会漏收。

如需更详细地了解充值流程，请阅读加密支付 Webhook 的工作原理和Webhook 投递保证。如有问题，请参阅支持页面。
