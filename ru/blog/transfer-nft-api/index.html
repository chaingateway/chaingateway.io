Перевод NFT через API: шаги, параметры и подводные камни

Как работает API для перевода NFT: проверка владения, параметры запроса, газ, подписание, подтверждение и частые ошибки в Ethereum и Tron с примерами ERC-721.

Эксперты по блокчейну

Проверил(а) Maurice Sobiera

API перевода NFT позволяет вашему бэкенду переместить токен между кошельками одним HTTP-запросом. Он проверяет владение, формирует вызов для стандарта токена, подписывает и отправляет транзакцию и сообщает о результате. Каждый перевод остаётся транзакцией в блокчейне, и комиссию платит отправитель.

Это руководство проходит по каждому шагу, параметрам, которые нужны запросу, и ошибкам, которые отнимают у разработчиков больше всего времени.

Коротко

  • Перевод NFT меняет владельца, записанного в контракте токена. В сетях типа Ethereum это вызов transferFrom или safeTransferFrom; в Solana это инструкция токена или Metaplex.
  • Запросу нужны четыре вещи: кошелёк отправителя, адрес получателя, адрес контракта (или минта) и ID токена. ERC-1155 также требует количество.
  • Проверяйте владение до отправки, оценивайте комиссии до подписи и подтверждайте успех по блокчейну (квитанция и событие Transfer), а не только по HTTP-ответу.
  • Чаще всего ломаются из-за неверной сети, получателей-контрактов, которые не могут принимать NFT, отсутствия нативного газа и устаревших данных о владении.
  • API убирает низкоуровневую работу под каждую сеть. Chaingateway отправляет переводы ERC-721, BEP-721 и TRC-721 и предлагает вебхуки для подтверждения, поэтому опрашивать не нужно. У него нет эндпоинта ERC-1155 и эндпоинта NFT для Solana.

Что делает API перевода NFT?

NFT — это запись в смарт-контракте (или в Solana — аккаунт токена), которая говорит, какой адрес владеет каким токеном. Перевести его значит изменить эту запись, и это может сделать только владелец или тот, кому владелец дал полномочия.

Стандарт ERC-721 определяет это на уровне контракта. Каждый токен идентифицируется ID токена, и перевод передаёт владение от одного адреса другому, когда его инициирует владелец, одобренный адрес или оператор. Затем контракт генерирует событие Transfer, которое слушают большинство индексаторов и систем уведомлений.

Поверх этого работает API. Хороший API берёт на себя пять задач:

  1. Проверка владения: подтвердить, что кошелёк отправителя сейчас владеет токеном.
  2. Формирование вызова: закодировать нужную функцию для стандарта и сети.
  3. Оценка комиссии: рассчитать газ или сетевую комиссию и проверить, хватит ли кошельку средств на неё.
  4. Подписание и отправка: подписать ключом кошелька и передать транзакцию в сеть.
  5. Отчёт о статусе: вернуть хеш транзакции и сообщить, когда перевод станет окончательным.

Альтернатива — собственная нода, библиотеки web3 под каждую сеть и самостоятельное кодирование. Это работает для одной сети и одной коллекции. Но становится дорого, когда добавляется вторая сеть.

Какие стандарты NFT и сети может покрыть API перевода?

Не каждый NFT — объект одного типа, поэтому API должен понимать больше одного диалекта.

Стандарт или модельСетиКак работает перевод
ERC-721Ethereum, Polygon, Arbitrum и другие EVM-сетиОдин ID токена на токен; transferFrom или safeTransferFrom
ERC-1155Ethereum и EVM-сетиКонтракт с несколькими токенами; перевод содержит количество для каждого ID, возможны пакетные переводы
SPL-токен с предложением один + метаданные MetaplexSolanaПеревод через программу токенов; метаданные хранятся отдельно

ERC-1155 стоит рассмотреть внимательнее, если вы работаете с игровыми предметами или билетами. Один контракт содержит и взаимозаменяемые, и невзаимозаменяемые типы, его интерфейс включает одиночные и безопасные пакетные переводы, а каждый перевод несёт количество для ID токена. Токен с предложением в один экземпляр ведёт себя как классический NFT, но тираж из 500 экземпляров — другой случай: нужно передать количество, а не только ID.

Solana устроена иначе. Там обычно не развёртывают отдельный контракт на каждую коллекцию. NFT — это токены программы токенов с предложением в один экземпляр, а Metaplex Token Metadata хранит данные NFT. Поэтому в Solana переводите по адресу минта, а не по паре контракт плюс ID токена, и получателю нужен аккаунт токена для этого минта.

Оценивая любого провайдера, спрашивайте, какие из этих трёх моделей он поддерживает и в каких сетях. Файл OpenAPI Chaingateway перечисляет такие эндпоинты NFT:

СетьЭндпоинтСтандарт
EthereumPOST /api/v2/ethereum/transactions/erc721ERC-721
PolygonPOST /api/v2/polygon/transactions/erc721ERC-721
ArbitrumPOST /api/v2/arbitrum/transactions/erc721ERC-721
BNB Smart ChainPOST /api/v2/bsc/transactions/bep721BEP-721
TronPOST /api/v2/tron/transactions/trc721TRC-721

Эндпоинта ERC-1155 нет. В Solana POST /api/v2/solana/transactions/SPL отправляет взаимозаменяемые токены SPL и не охватывает метаданные NFT или работу с тиражами, поэтому прежде чем полагаться на него, сверьте с ним свою коллекцию.

Как перевести NFT через API, шаг за шагом?

Поток одинаков для любого провайдера. Отличается лишь то, сколько из него вы пишете сами.

1. Проверьте владение

Прежде чем формировать транзакцию, подтвердите, что отправитель действительно владеет токеном. Для ERC-721 это значит спросить у контракта, кто владеет ID токена. Для ERC-1155 — проверить баланс этого ID для адреса. Для Solana — проверить аккаунт токена, который держит минт.

Делайте это непосредственно перед отправкой, а не по строке из кэша базы данных. NFT можно продать или переместить в секунды между вашей последней синхронизацией и запросом, а перевод с кошелька, который уже не владеет токеном, просто не пройдёт, и в некоторых сценариях сбоя всё равно потратит комиссию.

2. Проверьте полномочия

Стандарт разрешает инициировать перевод владельцу, одобренному адресу или оператору. Если ваш сервис переводит NFT с кошельков пользователей, которые вы не контролируете, сначала нужно одобрение. Если ваш сервис держит ключи кошельков, которые сам создал (как в кастодиальных потоках), отправляющий кошелёк является владельцем и одобрение не нужно.

3. Сформируйте и оцените

Выберите функцию и закодируйте аргументы. Затем оцените комиссию. В EVM-сетях это лимит газа, умноженный на цену газа; в Solana — небольшая комиссия за подпись плюс, возможно, аренда для нового аккаунта токена. Эндпоинты Chaingateway принимают необязательные поля gas, gasprice, maxFeePerGas и maxPriorityFeePerGas, а в EVM-сетях есть эндпоинт GET .../gasprice. Не задавайте лимит газа жёстко, потому что он ломается, когда получатель — контракт с дополнительной логикой. Проверьте в тестовой сети, сколько стоит запрос без этих полей.

Также убедитесь, что на кошельке достаточно нативной монеты. Адрес с десятью NFT и нулём ETH не сможет переместить ни один из них.

4. Подпишите и отправьте

Транзакцию должен подписать приватный ключ владельца. Либо вы подписываете локально и отправляете сырую транзакцию, либо API подписывает за кошелёк, которым управляет. Управляемые кошельки проще для бэкенд-потоков, потому что ваши серверы никогда не работают с сырыми ключами.

5. Подтвердите

Хеш транзакции означает, что сеть приняла вашу отправку, но не то, что перевод прошёл. Дождитесь квитанции с успешным статусом и события Transfer с ожидаемыми отправителем, получателем и ID токена. Для NFT высокой стоимости дождитесь нескольких подтверждений, прежде чем обновлять собственную базу или отдавать что-либо взамен.

Что нужно в запросе на перевод?

Каковы бы ни были названия полей у провайдера, запрос несёт одну и ту же информацию.

Последняя строка важнее, чем кажется. Если запрос завершился по таймауту, вы не знаете, отправилась ли транзакция. Слепой повтор может отправить вторую транзакцию: для уникального NFT она просто не пройдёт, но для издания ERC-1155 может перевести лишние экземпляры. Сначала найдите предыдущую попытку.

Как оценивать и платить комиссии за перевод NFT?

В EVM-сетях отправитель платит газ в нативной монете, и стоимость зависит от загруженности сети и сложности вызова. Простой transferFrom дешёвый по сравнению с минтом или продажей на маркетплейсе, но тяжёлая функция получения у контракта-получателя может его удорожить.

Практические правила:

  • Оценивайте непосредственно перед отправкой и добавляйте умеренный запас вместо фиксированного числа.
  • Держите минимальный баланс нативной монеты на каждом кошельке, который отправляет NFT, и настройте оповещение, когда он падает ниже этого уровня.
  • Если вы переводите от имени пользователей, заранее решите, кто платит: вы (пополняя кошелёк) или пользователь (списывая с баланса). Сюрпризы здесь превращаются в обращения в поддержку.
  • В Solana помните, что получателю может понадобиться новый аккаунт токена, и это разовая стоимость.

Как защитить переводы NFT?

Переводы NFT необратимы. В блокчейне нет возвратов платежей и службы поддержки, поэтому защита живёт в вашем коде.

Защитите путь подписания. Аутентифицируйте каждый вызов API. Chaingateway использует bearer-токен в заголовке Authorization, как определено в RFC 6750. Храните токен в хранилище секретов, меняйте его и никогда не передавайте в браузер или мобильное приложение. Кошельки, созданные с паролем, хранят ключ в зашифрованном виде на стороне Chaingateway. Кошельки без пароля возвращают приватный ключ при создании, и хранить его в безопасности должны вы.

Проверяйте получателя. Проверяйте формат адреса и сеть. Для предметов высокой стоимости предлагайте шаг подтверждения. Если политика требует, проверяйте адреса до отправки.

Учитывайте контракты-получатели. Спецификация ERC-721 описывает safeTransferFrom как вызов onERC721Received у контракта-получателя с откатом, если возвращаемое значение неверно. Это защищает от блокировки токена в контракте, который не может им распоряжаться. Обычный transferFrom оставляет эту проверку вызывающей стороне. Справочник API Chaingateway не говорит, какую из двух функций вызывает его эндпоинт ERC-721, поэтому прежде чем полагаться на любое из двух поведений, протестируйте перевод на адрес контракта в тестовой сети.

Ограничивайте риски. Держите горячий кошелёк только с NFT, нужными для ближайших переводов, а остальные — в более ограниченном кошельке. Применяйте лимиты на запрос и на день в собственном слое.

Логируйте всё. Записывайте, кто запросил перевод, параметры, хеш и результат. Когда клиент оспаривает перевод, блокчейн доказывает, что произошло, а ваши логи доказывают, кто это запросил.

Как подтверждать переводы вебхуками вместо опроса?

Опрос хеша транзакции каждые несколько секунд работает в прототипе, но в продакшене тратит запросы впустую. С вебхуками провайдер вызывает ваш эндпоинт, когда замечен подходящий перевод. В Chaingateway вы регистрируете вебхук с type, равным ERC721 (или TRC721, BEP721), и contractaddress, а также фильтр по адресу from или to. Уведомление содержит from, to, contractaddress, tokenid, txid и blocknumber.

Проверяйте заголовок X-Signature, отвечайте быстро и обрабатывайте события идемпотентно. Неудачные уведомления автоматически не повторяются, поэтому проверяйте и список неудачных уведомлений. Подпись покрывает только txid, поэтому сверяйте ID токена и получателя с собственными записями. Если вы хотите понять, как такие события выглядят на уровне логов, наш разбор события Transfer ERC-20 описывает структуру и топики. Событие ERC-721 следует тому же шаблону, где ID токена индексирован.

Что проверить перед запуском?

Прежде чем позволить реальным пользователям инициировать переводы NFT, пройдите этот список сначала в тестовой сети:

  1. Переведите принадлежащий вам токен на обычный кошелёк и проверьте квитанцию и событие Transfer.
  2. Переведите на контракт, который не может принимать NFT, и проверьте, что ваш код показывает ошибку.
  3. Попробуйте перевод с кошелька без нативной монеты и убедитесь, что ошибка понятна.
  4. Отправьте один и тот же запрос дважды и убедитесь, что проверка идемпотентности останавливает второй.
  5. Выключите эндпоинт вебхука на минуту, включите его обратно и убедитесь, что события не теряются и не обрабатываются дважды.
  6. Проверьте, кто может вызывать эндпоинт, с какими лимитами и где хранится секрет.

Часто задаваемые вопросы

Можно ли перевести NFT, не запуская собственную ноду?

Да. Размещённый блокчейн-API подключается к нодам за вас, формирует и отправляет транзакцию и возвращает хеш. Ключами кошелька всё равно нужно управлять самостоятельно или использовать управляемый кошелёк, а нативная монета для комиссий должна быть под рукой.

В чём разница между transferFrom и safeTransferFrom?

Обе функции меняют владельца в ERC-721. Безопасная версия также проверяет, что контракт-получатель реализует интерфейс получения, и откатывается, если нет. Это предотвращает застревание токенов, как сказано в спецификации ERC-721. Для автоматизированных потоков безопасная версия обычно лучший выбор по умолчанию.

Нужен ли другой вызов API для токенов ERC-1155?

На практике да. Переводы ERC-1155 несут количество для каждого ID токена и поддерживают пакетные переводы, как описано в стандарте ERC-1155. Запрос должен включать количество, а баланс после перевода нужно проверить. У Chaingateway нет эндпоинта ERC-1155, поэтому такие переводы требуют собственных вызовов контракта.

Как понять, что перевод прошёл?

Проверьте квитанцию транзакции на успешный статус и найдите соответствующее событие Transfer с правильными отправителем, получателем и ID токена. Вебхук может доставить это на ваш бэкенд сразу после включения в блок, поэтому опрашивать не нужно.

Можно ли вернуть переведённый NFT, если я ошибся?

Не вами. Вернуть его может только новый владелец. Поэтому проверяйте адреса, подтверждайте сеть и добавляйте шаг подтверждения для ценных токенов до отправки.
