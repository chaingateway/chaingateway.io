Перевод NFT через API: шаги, параметры и подводные камни

Как работает API для перевода NFT: проверка владения, параметры запроса, газ, подписание, подтверждение и частые ошибки в Ethereum и Solana, с практическим чек-листом.

API для передачи NFT позволяет вашему бэкенду перемещать токен из одного кошелька в другой с помощью одного HTTP-запроса, вместо того чтобы вашей команде приходилось писать вызовы контрактов, подписывать транзакции и управлять нодами вручную. Под капотом каждая передача по-прежнему является ончейн-транзакцией: задача API — проверить владение, сформировать правильный вызов для стандарта токена, оценить комиссии, подписать, отправить транзакцию и сообщить вам, что произошло. Это руководство проведет вас через каждый из этих шагов, параметры, необходимые для каждого запроса, и ошибки, которые отнимают у разработчиков больше всего времени.

Краткое содержание

  • Передача NFT меняет владельца, записанного в контракте токена. В сетях типа Ethereum это вызов transferFrom или safeTransferFrom; в Solana — инструкция токена или Metaplex.
  • Запрос требует четырех вещей: кошелек отправителя, адрес получателя, адрес контракта (или минта) и ID токена. ERC-1155 также требует указания количества.
  • Проверяйте владение перед отправкой, оценивайте комиссии перед подписанием и подтверждайте успех в сети (чекви и событие Transfer), а не только по HTTP-ответу.
  • Самые частые сбои: неверная сеть, контракты получателей, которые не могут принимать NFT, отсутствие нативного газа и устаревшее владение.
  • Унифицированный API устраняет необходимость настраивать инфраструктуру для каждой сети отдельно. Наш также поддерживает вебхуки для подтверждения, чтобы вам не приходилось опрашивать сеть.

Что на самом деле делает API для передачи NFT

NFT — это запись в смарт-контракте (или, в случае Solana, в токен-аккаунте), указывающая, какой адрес владеет каким токеном. Передача означает изменение этой записи, и делать это может только владелец или тот, кого владелец уполномочил.

Стандарт ERC-721 определяет это на уровне контракта. Каждый токен идентифицируется по ID токена, а передача переводит владение с одного адреса на другой, когда она инициируется владельцем, утвержденным адресом или оператором. Затем контракт генерирует событие Transfer — сигнал, за которым следят большинство индексаторов и систем уведомлений.

API находится поверх этого. Хороший API берет на себя пять задач:

  1. Проверка владения: подтверждение того, что кошелек отправителя в данный момент владеет токеном.
  2. Формирование вызова: кодирование правильной функции для стандарта и сети.
  3. Оценка комиссий: расчет газа или сетевых комиссий и проверка способности кошелька их оплатить.
  4. Подписание и трансляция: подписание ключом кошелька и отправка транзакции.
  5. Отчет о статусе: возврат хеша транзакции и уведомление о том, когда передача завершена.

Альтернатива — запуск собственного узла, хранение web3-библиотек для каждой цепочки и самостоятельная реализация кодирования. Это работает для одной цепочки и одной коллекции. Стоимость возрастает, когда вы добавляете вторую сеть.

Какие стандарты и цепочки может охватывать API перевода

Не каждый NFT представляет собой один и тот же тип объекта, поэтому API должен понимать более одного диалекта.

Стандарт / модельЦепочкиКак работает перевод
ERC-721Ethereum, Polygon, Arbitrum и другие EVM-цепочкиОдин идентификатор токена на токен; transferFrom или safeTransferFrom
ERC-1155Ethereum и EVM-цепочкиМульти-токен контракт; перевод включает количество для каждого идентификатора токена, с пакетными переводами
SPL-токен с предложением один + метаданные MetaplexSolanaПеревод через программу токенов; метаданные хранятся отдельно

ERC-1155 заслуживает более детального изучения, если вы работаете с игровыми предметами или билетами. Один контракт содержит как взаимозаменяемые, так и невзаимозаменяемые типы, его интерфейс включает одиночные и безопасные пакетные переводы, и каждый перевод несет количество для идентификатора токена. Токен с предложением в один ведет себя как классический NFT, но издание с предложением 500 — это другой случай: вы должны отправить количество, а не только идентификатор.

Solana работает иначе. Обычно она не развертывает отдельный контракт для каждой коллекции. Используется её Программа токенов с предложением минта в один, а Metaplex Token Metadata хранит детали NFT. Поэтому в Solana вы переводите по адресу минта, а не по контракту плюс идентификатор токена, и должны ожидать, что получателю понадобится токен-аккаунт для этого минта.

Когда вы оцениваете любого провайдера, спрашивайте, какие из этих трех моделей он поддерживает на каких цепочках. Blockchain API Chaingateway охватывает Ethereum, Bitcoin, Tron, Solana, Polygon, BNB Chain и Arbitrum, и поддерживает основные стандарты токенов, включая ERC-721, поэтому один и тот же паттерн интеграции применяется ко всем сетям, которые вы добавите позже.

Как перевести NFT через API, пошагово

Поток одинаков независимо от провайдера. Разница лишь в том, сколько из этого вам придется написать самостоятельно.

1. Проверьте владение

Перед построением транзакции убедитесь, что отправитель действительно владеет токеном. Для ERC-721 это означает запрос к контракту о том, кто владеет идентификатором токена. Для ERC-1155 — проверку баланса этого идентификатора для адреса. Для Solana — проверку токен-аккаунта, содержащего минт.

Делайте это непосредственно перед отправкой, а не из кэшированной строки базы данных. NFT могут быть проданы или перемещены за секунды между вашей последней синхронизацией и запросом, и перевод из кошелька, который больше не владеет токеном, просто завершится ошибкой и всё равно может стоить комиссии в некоторых режимах сбоя.

2. Проверьте авторизацию

Стандарт позволяет инициировать перевод владельцу, утвержденному адресу или оператору. Если ваш сервис перемещает NFT из пользовательских кошельков, которыми вы не управляете, вам сначала нужно утверждение. Если ваш сервис хранит ключи для созданных им кошельков (как в кастодиальных потоках), отправляющий кошелек является владельцем, и утверждение не требуется.

3. Постройте и оцените

Выберите функцию и закодируйте аргументы. Затем оцените комиссию. В EVM-цепочках это означает лимит газа, умноженный на цену газа; в Solana — небольшую комиссию за подпись плюс, возможно, ренту за новый токен-аккаунт. API с автоматической оценкой газа делает это за вас, поэтому вам не нужно жестко кодировать лимит газа, который провалится, когда получатель — контракт с дополнительной логикой.

Также убедитесь, что в кошельке достаточно нативной монеты. Адрес с десятью NFT и нулем ETH не сможет переместить ни один из них.

4. Подпишите и отправьте

Транзакция должна быть подписана закрытым ключом владельца. Либо вы подписываете локально и отправляете сырую транзакцию, либо API подписывает за кошелек, которым оно управляет. Управляемые кошельки проще для бэкенд-процессов, так как ваши серверы никогда не работают с сырыми ключами.

5. Подтвердите

Хеш транзакции означает, что сеть приняла вашу отправку, а не то, что перевод прошел успешно. Дождитесь получения чека (receipt) со статусом успеха и события Transfer с ожидаемым отправителем, получателем и ID токена. Для высокоценных NFT дождитесь нескольких подтверждений, прежде чем обновлять свою базу данных или выпускать что-либо в обмен.

Слепой повтор может отправить вторую транзакцию, которая для уникального NFT просто упадет с ошибкой, но для выпуска ERC-1155 может переместить лишние копии. Сначала проверьте предыдущую попытку.

Комиссии: оценка и оплата

В EVM-сетях отправитель платит газ нативной монетой цепи, а стоимость варьируется в зависимости от загрузки сети и сложности вызова. Обычный transferFrom дешевле минта или продажи на маркетплейсе, но контракт-получатель с тяжелой функцией-приемником может поднять цену.

Практические правила:

  • Оценивайте газ непосредственно перед отправкой и добавляйте небольшой буфер вместо использования фиксированного числа.
  • Держите минимальный нативный баланс на каждом кошельке, отправляющем NFT, и настраивайте алерты, когда он падает ниже порога.
  • Если вы переводите от имени пользователей, решите заранее, кто платит: вы (пополняете кошелек) или пользователь (списываете с баланса). Неожиданности здесь превращаются в тикеты в поддержку.
  • В Solana помните, что получателю может понадобиться новый токен-аккаунт, что имеет разовую стоимость.

Меры безопасности

Переводы NFT необратимы. Нет чарджбэков и нет службы поддержки в цепи, поэтому защита живет в вашем коде.

Защитите путь подписания. Аутентифицируйте каждый вызов API. Chaingateway подписывает запросы с помощью HMAC, поэтому запрос, измененный в пути или отправленный кем-то без секрета, будет отклонен. Храните секрет в хранилище, ротируйте его и никогда не отправляйте его в браузер или мобильное приложение.

Проверяйте получателя. Проверяйте формат адреса и сеть. Предлагайте шаг подтверждения для высокоценных предметов. Там, где политика это требует, проверяйте адреса перед отправкой.

Учитывайте контракты-получатели. Спецификация ERC-721 описывает safeTransferFrom как проверку, когда адрес назначения является контрактом, того, что он реализует интерфейс получателя, и отмену транзакции, если это не так. Использование безопасного варианта защищает вас от блокировки токена в контракте, который не может его переместить. Обычный transferFrom оставляет эту ответственность вызывающему.

Ограничьте риски. Храните в горячем кошельке только те NFT, которые нужны для ближайших переводов, а остальные — в кошельке с более строгими ограничениями. Применяйте лимиты на запрос и суточные лимиты на своем уровне.

Логируйте всё. Записывайте, кто запросил перевод, параметры, хеш и результат. Когда клиент оспаривает перевод, блокчейн доказывает, что произошло, а ваши логи — кто об этом просил.

Подтверждение переводов через вебхуки вместо опроса

Опрос хеша транзакции каждые несколько секунд работает в прототипе и тратит запросы в продакшене. Вебхуки меняют модель: провайдер вызывает ваш эндпоинт, когда перевод замайнен, с декодированными данными об отправителе, получателе и токене. Проверяйте подпись на каждом входящем вызове, отвечайте быстро и обрабатывайте события идемпотентно, так как доставки могут повторяться. Если вы хотите понять, как такие события выглядят на уровне логов, наш разбор события ERC-20 Transfer охватывает структуру и топики, а событие ERC-721 следует тому же шаблону с индексированным ID токена.

Наша перспектива

Большинство команд недооценивают переводы NFT, потому что «счастливый путь» — это один вызов функции. Работа заключается во всем, что вокруг: в какой сети, чей газ, что происходит при повторной попытке, как вы узнаете результат. Мы создали Chaingateway, чтобы разработчик не нес ответственность за эту поверхность атаки. Один REST API заменяет эндпоинты для конкретных цепочек и ваши собственные ноды, ответы приходят уже декодированными, так что вам не нужно парсить логи вручную, газ оценивается автоматически, а запросы подписываются HMAC.

Наш совет — проектируйте сначала для случаев сбоев. Решите, кто платит комиссии, что считается подтверждением и как распознается повторная попытка, и сам вызов перевода станет легкой частью. Чек-лист перед запуском

Прежде чем позволить реальным пользователям инициировать переводы NFT, пройдитесь по этому списку в тестовой сети:

  1. Переведите принадлежащий вам токен на обычный кошелёк и подтвердите получение и событие Transfer.
  2. Переведите на контракт, который не может принимать NFT, и убедитесь, что ваш код корректно обрабатывает ошибку.
  3. Попробуйте выполнить перевод с кошелька, у которого нет нативной монеты, и убедитесь, что ошибка понятна.
  4. Отправьте один и тот же запрос дважды и убедитесь, что ваша проверка идемпотентности блокирует второй.
  5. Отключите свою конечную точку вебхука на минуту, восстановите её и убедитесь, что события не потеряны и не обработаны дважды.
  6. Проверьте, кто может вызывать конечную точку, с какими лимитами и где хранится секрет.
